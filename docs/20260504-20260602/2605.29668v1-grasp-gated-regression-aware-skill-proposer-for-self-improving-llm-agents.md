## 摘要
在结构化环境中运行的LLM智能体以操作方式而非对话方式失败，其可靠性取决于对环境的程序性知识。先前的自我改进方法积累自然语言指导，但不检查每个新项目是否保留了先前正确的行为，因此修复一条轨迹的注释可能无声地回归另一条轨迹。我们提出GRASP（门控回归感知技能提议器），它将智能体改进视为对受限技能库的一系列编辑，仅在候选技能在硬回归预算下对平衡保留探针产生净改进时才接受它。我们在两个基于FHIR的临床基准上评估了GRASP在五个基础模型（gpt-oss-120b、DeepSeek V4 Flash、Gemini 3.1 Flash Lite、GPT-4.1、GPT-5.4）上的表现。在MedAgentBench上，GRASP将gpt-oss-120b从40.6%提升至88.8%，比五个自我改进基线中最强的超出21.0个百分点，并将其他每个基础模型提升17.2至40.3个百分点。消融实验将增益归因于比较性提议生成、接受门和硬回归预算，而非技能编写本身——没有验证时，技能编写并不比不使用技能更好。该机制泛化到临床领域之外，在四个非临床环境中的三个上改进了智能体，仅在动作空间开放的情况下保持持平。冻结的技能库跨模型转移，来自较强模型的技能可以改进较弱执行者超出其自身所学，而反向则不然，这种不对称性是无门控基线无法复现的。

## Abstract
LLM agents acting in structured environments fail in operational rather than conversational ways, and reliability depends on procedural knowledge of the environment. Prior self-improvement methods accumulate natural-language guidance without checking that each new item preserves previously correct behavior, so a note that fixes one trajectory can silently regress another. We introduce GRASP (Gated Regression-Aware Skill Proposer), which treats agent improvement as a sequence of edits to a bounded skill library, admitting each candidate only if it produces a net improvement on a balanced held-out probe under a hard regression budget. We evaluate GRASP across five base models (gpt-oss-120b, DeepSeek V4 Flash, Gemini 3.1 Flash Lite, GPT-4.1, GPT-5.4) on two FHIR-based clinical benchmarks. On MedAgentBench, GRASP lifts gpt-oss-120b from 40.6% to 88.8%, exceeds the strongest of five self-improvement baselines by 21.0 points, and improves every other base model by 17.2 to 40.3 points. Ablations attribute the gain to comparative proposal generation, the acceptance gate, and the hard regression budget rather than to skill writing itself, which without validation is no better than using no skills. The mechanism generalizes beyond the clinical domain, improving agents on three of four non-clinical environments and remaining flat only where the action space is open-ended. Frozen libraries transfer across models, where skills from a stronger model improve weaker executors beyond what they learn for themselves while the reverse does not, an asymmetry that no ungated baseline reproduces.

# 论文总结：GRASP: Gated Regression-Aware Skill Proposer for Self-Improving LLM Agents

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：LLM 智能体在结构化环境（如电子健康记录 EHR、数据库、Web 界面）中经常因违反操作规则而失败。这类失败具有**操作性**本质，而非对话能力不足。现有自我改进方法（如 Reflexion、ExpeL）通过累加自然语言指导来修复错误，但**缺乏验证**：一条修复某条轨迹的备注可能**无声地破坏**另一条原本正确的轨迹。随着指导不断累积，任务相关内容被稀释，导致性能退化。
- **整体含义**：作者认为智能体改进应被建模为对**有限技能库**的**已验证编辑**，而非单调累加。GRASP 通过回归感知的门控机制，确保每次更新在修复旧错误的同时不引入新回归，从而实现可靠的自改进。

## 2. 提出的方法论

### 核心思想
- 将智能体自改进视为对**有界技能库**的序列编辑（添加、修改、删除技能），每次候选编辑需通过**平衡探针**（包含等量之前失败和之前成功的样例）的验证，满足**硬回归预算**（净修复>净回归，且回归不增加）才被接受。

### 关键技术细节

| 组件 | 描述 |
|------|------|
| **技能定义** | 结构化行为指令，包含触发条件、规则、验证步骤、对比示例。用 Markdown + YAML 表示，可审计、可版本控制。库容量有界（≤10）。 |
| **失败驱动技能提议** | 每批训练后，失败轨迹被 LLM 分类器按失败机制分组。技能编写模型针对最频繁的失败组生成 K 个候选编辑（ADD/MODIFY/REMOVE）。 |
| **回归感知选择** | 构建包含 N/2 个之前失败 + N/2 个之前成功的探针。对当前库 S 和每个候选库 Sc 分别运行探针，计算修复数 F 和回归数 R。接受条件：\( (F^{(c)}-F_0) - (R^{(c)}-R_0) > 0 \) 且 \( R^{(c)} \leq R_0 \)。 |
| **对比性修订** | 若最佳候选导致回归，技能编写模型根据回归样例生成更窄的版本，仅当修订得分更高且满足预算才替换原候选。 |
| **无效动作回归加权** | 无效动作的回归在得分中加权 λ=2，但硬预算使用未加权计数。 |

### 算法流程（文字说明）
1. 运行当前库 S 执行一批开发集轨迹，记录成功/失败。
2. 将失败轨迹按失败机制分类（LLM 分类）。
3. 由技能编写模型生成 K 个候选编辑（按组大小从大到小循环生成）。
4. 从先前完成的轨迹中采样 N/2 失败 + N/2 成功样例构建探针（与当前批次无重叠）。
5. 在当前库 S 上运行探针得到基线 \(F_0, R_0\)。
6. 对每个候选库 Sc 运行同一探针得到 \(F^{(c)}, R^{(c)}\)，计算得分。
7. 选择满足净改进和回归预算的最佳候选，若有回归则尝试修订，否则保持库不变。

## 3. 实验设计

### 数据集与场景
- **主要临床基准**（基于 FHIR）：
  - **MedAgentBench**：10 种任务类型，300 样本，包含资源检索、药物协调等。
  - **MedAgentBench-v2**：10 种新任务类型，增加多步决策和安全协议。
  - **FHIR-AgentBench**：只读临床 QA，基于 MIMIC-IV FHIR 数据。
- **非临床环境**（AgentBench）：
  - ALFWorld、WebShop、DBBench、OS Interaction（用于泛化测试）。
- 每个基准分为开发、验证、测试（+ OOD 分裂用于 MedAgentBench 变体）。

### 对比方法
- **无技能基线**（No skills）
- **序列记忆**（Sequential Memory）：每失败后追加自然语言修正。
- **批记忆**（Batch Memory）：每批更新一次，与 GRASP 频率相同。
- **ExpeL**：从对比配对中提取规则，有界规则列表（上限 20）。
- **Evo-MedAgent**：情景+语义记忆，顶层检索，无探针验证。
- **SkillX**：从成功轨迹提取技能，按令牌重叠检索，无回归控制。
- **GRASP（本文）**。

### 模型
- 5 种基础模型：gpt-oss-120b（开源 H200 自托管）、DeepSeek V4 Flash、Gemini 3.1 Flash Lite、GPT-4.1、GPT-5.4（低推理努力）。

### 训练协议
- 每方法训练 5 个 epoch，批大小 48 集。
- 每 epoch 后计算验证准确率，保存最佳 checkpoint 用于测试。
- 测试/OOD 仅在最终 checkpoint 上评估一次。
- GRASP 探针大小 N=36，候选数 K=4。
- 报告平均值±标准差（开源 5 种子，专有 3 种子）。

## 6. 主要结论与发现

1. **GRASP 显著优于所有基线**：在 MedAgentBench 上，gpt-oss-120b 从 40.6% 提升至 88.8%，超过最强基线 21.0 点；其他模型提升 17.2-40.3 点。
2. **增益源于验证门而非技能编写**：无门控（K=1）时性能等于无技能基线（40.1%），比较生成（K=4 无门）改善有限（63.5%），加门后达到 88.8%。
3. **技能库可跨模型迁移**：强模型（GPT-5.4）编写的技能提升弱执行者超过其自训，弱模型技能则不能；不对称性无门控基线无法复现。
4. **泛化到非临床环境**：在 ALFWorld、WebShop、DBBench 上提升，在 OS Interaction（开放动作空间）上无提升。
5. **技能库编码环境程序性知识而非模型特定模式**：跨基准迁移仅在共享交互规范时有效（MedAgentBench ↔ v2），迁移到不同接口的 FHIR-AgentBench 会退化。
6. **有界库比无界记忆更高效、更稳定**：GRASP 使用十分之一推理 tokens 达到更高准确率，且训练曲线单调上升，而基线振荡或退化。

## 7. 优点

- **方法创新**：首次将回归感知的门控探针用于技能库编辑，解决了单调累加带来的退化问题。
- **广泛验证**：涵盖 5 个基础模型、7 个基准（3 临床+4 非临床）、5 个基线、8 个消融、跨模型/跨基准迁移。
- **公平比较**：所有方法共享相同代码框架、注入位置、训练数据、解码设置。
- **统计严谨**：报告均值±标准差、bootstrap CI、Cohen's d、置换检验 p 值。
- **实用特性**：结论强调**可审计性**（每个技能来自哪个失败、得分多少、替换了谁），且使用有界库降低推理成本。
- **开源**：代码、技能库、全部结果已公开。

## 8. 不足与局限

- **实验覆盖偏差**：
  - 所有临床基准基于**模拟 FHIR 环境**，不涉及真实临床工作流、患者记录不完整、自由文本、多系统集成等复杂因素。
  - 非临床仅测试 4 个环境，且 OS Interaction 无增益（开放空间），泛化性有限。
- **成本问题**：
  - 训练开销主要来自探针验证（每批约 440 次 agent 调用），虽推理成本低但在开发阶段昂贵。若生产环境探针样本难以获取，需减小探针大小（可能牺牲可靠性）。
- **跨模型迁移不对称**：
  - 只有强写手→弱执行者方向有效；弱写手→强执行者反而变差。实际部署时需选择更强的写手模型，但论文未提供自动检测写手与执行者匹配度的方法。
- **API 模型不稳定性**：
  - GPT-4.1、GPT-5.4、Gemini 3.1 Flash Lite 通过 API 访问，可能随时更新或改变行为，结果的可复现性受限于特定快照（已提供访问日期）。
- **统计效力**：
  - 专有模型仅 3 种子，导致某些对比的置换检验 p 值受限于最小值（例如 p=0.10 时无法拒绝零假设），虽 bootstrap CI 排除了零。
- **超参数搜索不彻底**：仅进行单变量扫描，未探索交互效应（如 B×N×K 组合）。
- **未评估实时临床适用性**：技能是为通过基准而生成的程序性策略，非医疗专业知识；部署前需临床专家审查、前瞻性对比和实时监控。
