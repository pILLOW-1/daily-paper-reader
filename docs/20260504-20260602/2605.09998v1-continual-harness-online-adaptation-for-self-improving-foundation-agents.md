## 摘要
编程框架（如Claude Code和OpenHands）为基础模型提供了工具、记忆和规划，但针对具身主体的长时域部分可观测决策，尚无等效方案。我们首先报告了我们的Gemini玩宝可梦（GPP）实验。通过迭代式人在回路框架优化，GPP成为首个完成宝可梦蓝、黄遗产（困难模式）和晶（无败战）的AI系统。在最具挑战的阶段，主体自身开始通过长上下文记忆迭代其策略，展现出涌现的自我改进信号，同时伴随人在回路优化。持续框架完全将人移出回路：一个无重置的、自我改进的具身主体框架，将我们观察到的现象形式化并自动化。仅从最小的环境接口开始，主体交替进行行动和完善自身的提示、子主体、技能和记忆，利用任何过去的轨迹数据。提示优化方法需要情节重置；而持续框架在单次运行内进行在线适应。在宝可梦红和绿宝石上，跨前沿模型，从零开始的持续框架相比最简基线大幅降低了按键成本，并弥补了与手工专家框架之间的大部分差距（能力依赖性提升），尽管起点是相同的原始接口，没有 curated 知识、手工工具或领域脚手架。然后我们通过模型自身闭合回路：一个在线过程奖励共学习循环，其中开源主体通过优化框架的 rollout 被前沿教师重新标注并用于更新模型，在训练迭代之间无需重置环境的情况下，推动宝可梦红中持续的游戏里程碑进展。

## Abstract
Coding harnesses such as Claude Code and OpenHands wrap foundation models with tools, memory, and planning, but no equivalent exists for embodied agents' long-horizon partial-observability decision-making. We first report our Gemini Plays Pokemon (GPP) experiments. With iterative human-in-the-loop harness refinement, GPP became the first AI system to complete Pokemon Blue, Yellow Legacy on hard mode, and Crystal without a lost battle. In the hardest stages, the agent itself began iterating on its strategy through long-context memory, surfacing emergent self-improvement signals alongside human-in-the-loop refinement. Continual Harness removes the human fully from this loop: a reset-free self-improving harness for embodied agents that formalizes and automates what we observed. Starting from only a minimal environment interface, the agent alternates between acting and refining its own prompt, sub-agents, skills, and memory, drawing on any past trajectory data. Prompt-optimization methods require episode resets; Continual Harness adapts online within a single run. On Pokemon Red and Emerald across frontier models, Continual Harness starting from scratch substantially reduces button-press cost relative to the minimalist baseline and recovers a majority of the gap to a hand-engineered expert harness, with capability-dependent gains, despite starting from the same raw interface with no curated knowledge, no hand-crafted tools, and no domain scaffolding. We then close the loop with the model itself: an online process-reward co-learning loop, in which an open-source agent's rollouts through the refining harness are relabeled by a frontier teacher and used to update the model, drives sustained in-game milestone progress on Pokemon Red without resetting the environment between training iterations.

- **整体含义**：提出一个**无需重置、在线自我改进**的框架，使具身代理能从最小接口开始，在单次运行中通过内省和编辑自身提示、子代理、技能和记忆来持续提升能力，并能与开源模型的权重更新形成共学习循环。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- ** Continual Harness**：一个双循环架构，代理交替执行“行动”和“完善框架”两个角色。
- **无重置原则**：所有更新发生在同一连续情节（episode）内，无需重启环境，可处理**仅在长情节后期出现的失败模式**。

### 关键技术细节
1. **框架状态定义**：由四个组件组成：
   - **系统提示 p**：模型推理时的指令和策略指导。
   - **子代理 G**：专门的模块（如战斗策略、解谜、自省）。
   - **技能 K**：可重用的例程（路径规划、工具包装）。
   - **记忆 M**：跨轨迹积累的事实、策略和观察。

2. **内循环（代理步骤）**：
   - 代理接收观测 (帧 + 文本地图)、当前框架状态和轨迹历史，输出动作。  
   - 动作从固定按钮集合中选择。

3. **外循环（框架精炼）**：每 F 步（经过 W 步预热后），**精炼器**读取最近一段轨迹窗口，识别失败特征（导航循环、工具调用失败、目标卡住、遗漏探索），然后对四个组件分别执行 CRUD 操作：
   - 重写系统提示；  
   - 创建/编辑/删除子代理；  
   - 将成功序列编码为技能/修复出错代码；  
   - 更新记忆条目（添加、修正、降权）。  

4. **精炼器与代理共享同一模型**（实验中为 Gemini 3 系列），通过同一套元工具 API 执行编辑；区别仅在于被调用时机和上下文。

5. **模型-框架共学习循环**：
   - 在无重置的在线迭代中，每个迭代运行 $K=256$ 步，轨迹分布受当前模型参数 $\theta$ 和实时精炼框架 $H_t$ 共同影响。  
   - 每步由过程奖励模型（PRM）评分，低奖励窗口被**前沿教师模型（Gemini-3.1-pro）** 重新标注。  
   - 使用软 SFT（LoRA）更新学生模型参数 $\theta$。  
   - 迭代间不重置游戏状态，代理位置累积。

## 3. 实验设计

- **环境和任务**：
  - **宝可梦红**（Game Boy）和**宝可梦绿宝石**（GBA）：两个长时域、部分可观测的RPG。
  - 接口：屏幕帧 + ASCII 文本地图 + 8个按钮（UP/DOWN/LEFT/RIGHT/A/B/START/SELECT），无攻略、无工具、无领域知识。
  - 评估指标：**累积按键次数**到标准化里程碑（红18个里程碑，绿宝石31个）。

- **对比条件**：
  - **Hmin**：最简基线（只有通用系统提示，无子代理、记忆或技能）。
  - **Hexpert**：手工专家框架（含子代理、A*路径规划、类型表、伤害计算器等）。
  - **HCH**：Continuous Harness，含三种变体：
    - *from scratch*：从零开始精炼。
    - *bootstrap frozen*：加载一次成功运行的框架并冻结，不继续精炼。
    - *bootstrap updating*：加载成功框架并继续精炼。

- **使用的模型**：
  - 内循环代理和精炼器：**Gemini 3 系列**（Pro, Flash, Flash-Lite）。
  - 共学习学生模型：**Gemma-4**（E2B, E4B, 26B MoE, 31B dense）。
  - 教师模型：**Gemini-3.1-pro**。

- **消融实验**：

## 6. 论文的主要结论与发现

1. **GPP项目突破**：首次实现AI系统完整通关多个宝可梦RPG（红、黄遗产困难模式、晶无败战），证明了人工框架精炼的有效性。
2. **Continual Harness 有效性**：在红和绿宝石上，从零开始的 HCH 显著降低按键成本，恢复了从 Hmin 到 Hexpert 的大部分差距（约40%成本降低），且无需任何领域知识。
3. **能力依赖性**：框架增益依赖于模型能力——在 Gemin Pro 上严格帕累托支配最简基线，在 Flash 上高方差，在 Flash-Lite 上无法自举（甚至劣于基线）。
4. **技能可度量自我改进**：路径技能在单次运行中从约50%的额外路径成本下降到个位数，接近 Dijkstra 最优。
5. **开源模型共学习**：Gemma-4 模型通过 DAgger+PRM 在线迭代，在无环境重置的情况下持续推进游戏里程碑（从前端和中端检查点均有效）。
6. **无重置优势**：失败特征在长轨迹中积累，精炼质量随情节长度而提升；可处理仅在后期出现的失败模式。

## 7. 优点

- **创新性**：首次提出**无重置、在线、全组件自精炼**框架，超越了仅优化提示的现有方法。
- **自动化程度高**：从最小接口开始自动构建子代理、技能和记忆，无需手工设计。
- **普适性与可迁移性**：框架精炼的产物（技能、记忆）可在不同运行间引导转移（bootstrap），减少冷启动开销。
- **共学习闭环**：将模型权重更新与框架精炼耦合，实现在线持续进步，并且框架和模型在同一个轨迹分布中协同演化。
- **评估严谨**：使用标准化里程碑和累积按键成本，提供细粒度过程奖励分解；提供多个种子和个体轨迹的可视化。

## 8. 不足与局限

- **能力下限**：对较弱模型（Flash-Lite 和 Gemma-4 小参数量）无法自举，框架精炼在能力不足时反而有害。
- **共学习未收敛**：实验报告了持续进步但尚未达到收敛点，也未与重置式共学习进行头对头比较。
- **领域有限**：仅测试于宝可梦系列游戏，泛化到其他具身环境尚未验证。
- **依赖教师模型**：共学习中学生模型依靠前沿教师（Gemini-3.1-pro）重标轨迹，无法用自身作教师；更高参数量开源模型的可能性未探索。
- **子代理放弃问题**：在引导更新中，红游戏上的代理偶尔放弃继承的子代理转而新建，导致性能下降。
- **计算成本**：虽然按键成本降低，但精炼过程本身消耗大量 token（API 费用），论文未提供完整经济性分析。
- **部分组件未被充分利用**：大部分创建的技能从未被调用，记忆重用率较低，说明框架在资源分配上仍有浪费。
