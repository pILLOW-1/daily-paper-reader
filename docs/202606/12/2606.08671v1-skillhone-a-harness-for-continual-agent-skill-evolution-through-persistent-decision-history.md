## 摘要
智能体技能为语言模型智能体提供了任务特定的流程、脚本和参考，但这些技能所针对的任务和环境不断变化。现有方法在有限运行中改进技能，仅保留最终产物，丢弃了后续智能体为解释先前修订、评估和已拒绝替代方案所需的决策历史。我们提出SkillHone，一种基于持久决策历史的智能体技能持续演进工具。SkillHone将技能修订与提供实践反馈的评估侧证据配对，记录了诊断、修订、证据和结果的结构化历史。角色分离的子智能体在带有编辑报告的实践探针上运行候选技能，并根据先前决策提出修订，从而无需重新发现过往理由即可实现跨会话优化。我们在原始开放网络环境下使用深度研究基准评估SkillHone，其中智能体未获得集成搜索栈，必须通过可移植技能组织检索。我们将结果与由商业检索服务支持的深度研究智能体进行比较。以Qwen3.6-35B-A3B作为评估时主干，所得技能在GAIA上比深度研究智能体高出15.8分，在WebWalkerQA-EN上高出3.2分，同时也超越了先前的技能演进方法。

## Abstract
Agent skills extend language-model agents with task-specific procedures, scripts, and references, but the tasks and environments they target continually change. Existing methods improve skills in bounded runs and retain only the final artifact, discarding the decision history that later agents need to interpret prior revisions, evaluations, and rejected alternatives. We introduce SkillHone, a harness for continual agent skill evolution grounded in persistent decision history. SkillHone pairs skill revisions with evaluation-side evidence that supplies practice feedback, recording structured histories of diagnoses, revisions, evidence, and outcomes. Role-separated subagents run candidate skills on practice probes with redacted reporting and propose revisions informed by prior decisions, enabling cross-session refinement without rediscovering past rationale. We evaluate SkillHone on deep-research benchmarks in a raw open-web setting, where agents are not given an integrated search stack and must organize retrieval through portable skills. We compare against a deep-research agent backed by commercial retrieval services. With Qwen3.6-35B-A3B as the evaluation-time backbone, the resulting skills outperform the deep-research agent by 15.8 points on GAIA and 3.2 points on WebWalkerQA-EN, while also exceeding prior skill-evolution methods.

## 论文《SkillHone：通过持久决策历史实现智能体技能持续演进的工具》详细总结

### 1. 核心问题与整体含义（研究动机与背景）

*   **核心问题**：现有的智能体技能优化方法（如 Skill-Creator、Hermes-SE）通常将改进过程视为一个**有限回合**的运行，优化结束后仅保留最终版本的技能产物。然而，这种**以产物为核心**的视角丢弃了整个优化过程中产生的**决策历史**，包括：
    *   促使修订的问题诊断是什么？
    *   考虑了哪些被拒绝的替代方案？
    *   支持决策的评估证据是什么？
    *   特定修订最终被接受或拒绝的原因是什么？
*   **后果**：当环境变化或任务分布发生偏移需要再次优化时，后续的智能体无法利用过去的经验。它们可能重复过去的修复、撤销有用的更改，或者在丢失上下文的情况下继续优化，导致**效率低下**和**方向错误**。
*   **研究动机**：为了解决智能体技能的**持续性维护**问题，需要一种机制来捕获、存储和利用整个技能演化过程中的结构化决策历史，使智能体能够跨会话地、增量式地改进技能，而无需每次都从头开始。

### 2. 方法论：核心思想、技术细节与算法流程

*   **核心思想**：将技能演化视为一个**持续的过程**，通过记录和维护**持久化的决策历史**，将每次诊断、修订、评估和决策都结构化地保存下来。这样，后续的优化才能基于完整上下文，避免重复劳动和错误回归。
*   **核心架构**：
    *   **SkillHone Harness**：一个轻量级的编排框架，包含两个核心仓库：
        *   **技能仓库 (Skill Repository)**：存储不断演进的技能包（`SKILL.md`、脚本、模板等）。
        *   **评估仓库 (Evaluation Repository)**：存储用于评估的探针任务、验证器、执行轨迹等评估资产。
    *   **角色分离的子代理团队**：一个动态调度器（Dispatcher）按需创建两种权限边界的子代理：
        *   **优化端团队 (Optimization Subagent Team)**：负责诊断问题、提出修订（`r_t`）、修改技能仓库。他们**只能**访问**编辑后的 (redacted)** 问题报告和先前的决策历史，**不能**接触完整的探针目标或验证器。
        *   **评估端团队 (Evaluation Subagent Team)**：负责运行候选技能，分析执行轨迹，并生成包含诊断信息的**编辑后的问题报告**给优化端。他们**只能**读取评估仓库中的信息，**不能**修改技能仓库。
*   **关键技术细节**：
    *   **持久决策历史 (Persistent Decision History)**：每一步优化都生成一个结构化的决策记录，包含四个要素：
        *   **诊断 (Diagnosis, `q_t`)**：对当前失败原因的分析。
        *   **修订 (Revision, `r_t`)**：提出的具体修改方案。
        *   **证据 (Evidence, `e_t`)**：来自评估端的编辑后的评估结果。
        *   **结果 (Outcome, `o_t`)**：修订是否被接受、拒绝、需要修改或延迟。
        *   历史记录 `H_t = {h_1, ..., h_t}` 在整个演化会话之间持久保存。
    *   **编辑后的评估反馈 (Redacted Evaluation Feedback)**：评估端向优化端返回的报告会过滤掉直接暴露答案或验证器的信息，只能示失败模式、聚合结果等诊断性证据。这避免了优化过程“记住”正确答案，保证了泛化能力。
*   **算法流程描述**：
    1.  **初始化**：初始化技能 `S0` 和决策历史 `H0`。
    2.  **循环迭代** (t = 0 到 T-1)：
        a.  **多维度评估**：评估端代理使用当前技能 `St` 在评估仓库上运行，并生成编辑后的问题报告 `E_t`。
        b.  **诊断与提案**：优化端代理读取历史 `H_t` 和报告 `E_t`，形成诊断 `q_t` 并提议修订 `r_t`。
        c.  **针对性评估**：评估端代理运行修订后的候选技能，并只将编辑后的证据 `e_t` 反馈给优化端。
        d.  **决策与记录**：优化端根据证据做出是否接受的决定 `o_t`。如果接受，则更新技能为 `S_(t+1)`。无论是否接受，都将本次步骤的完整记录（诊断、修订、证据、结果）追加到持久决策历史 `H_(t+1)` 中。
    3.  **输出**：返回最终的技能 `S_T` 和完整的决策历史 `H_T`。
