## 摘要
代理技能让大语言模型代理能够复用指令、资源、工具和工作流，但同时也为恶意行为提供了新的藏身之处。一个技能在其文档或代码中可能看似无害，但只有在与特定用户请求、本地资产、持久状态或多步骤工具交互调用时才会变得有害。这使得纯静态审查变得脆弱。我们提出运行时技能审计（RSA），一种动态分析方法，通过探查技能中介的代理在目标运行时条件下实际执行的操作来审计技能。RSA并非使用相同的通用任务测试每个技能，而是刻画风险相关接口，准备执行上下文以触发这些接口，并根据产生的痕迹证据分配安全标签。我们在OpenClaw上实现了RSA，并在100个技能上将其与代表性静态基线进行了评估。RSA实现了90.0%的准确率，88.0%的真阳性率和8.0%的假阳性率，相比最佳静态基线准确率提升了13.0个百分点。面对自我演化的攻击，静态检测器在一两轮后崩溃，而RSA在每轮中仍然能检测出20个恶意技能中的19-20个。

## Abstract
Agent skills let LLM agents reuse instructions, resources, tools, and workflows, but they also create a new place for malicious behavior to hide. A skill may look benign in its documentation or code while becoming harmful only when it is invoked with particular user requests, local assets, persistent state, or multi-step tool interactions. This makes purely static vetting brittle. We present Runtime Skill Audit (RSA), a dynamic analysis method that audits skills by asking what the skill-mediated agent actually does under targeted runtime conditions. Instead of testing every skill with the same generic tasks, RSA profiles risk-relevant interfaces, prepares the execution context needed to exercise them, and assigns security labels from the resulting trace evidence. We instantiate RSA on OpenClaw and evaluate it on 100 skills against representative static baselines. RSA achieves 90.0\% accuracy with an 88.0\% true positive rate and an 8.0\% false positive rate, improving accuracy by 13.0 percentage points over the best static baseline. Under self-evolving attacks, static detectors collapse after one or two rounds, while RSA continues to detect 19--20 out of 20 malicious skills across rounds.

# 2. 方法论

- **核心思想**：Runtime Skill Audit (RSA) 是一种动态分析方法，通过**风险引导的任务生成**、**上下文感知的运行时执行**和**痕迹驱动的判断**三个原则，将技能审计转变为对“技能中介代理在目标运行时条件下实际做了什么”的考察。
- **关键技术细节**：
  - **风险引导的技能剖析与任务生成**：先使用LLM分析技能工件，推断其调用的平台工具，映射到安全相关的能力组（如文件访问、shell执行、网络交互、内存操作等），生成结构化安全画像。然后从画像生成针对性任务（而非通用任务），任务包含用户请求、沙箱准备、执行约束等。
  - **上下文感知的运行时执行**：在隔离的沙箱代理环境中执行任务，准备相关文件、凭据、持久状态等运行时上下文。执行期间记录结构化踪迹（工具调用、文件读写、网络请求、内存交互、错误/拒绝等）。若执行失败，使用有限的自修复循环（如更新任务、调整准备文件、增加超时等）重新运行；对缺失的外部应用使用确定性假应用垫片记录行为。
  - **痕迹驱动的判断**：根据运行时踪迹证据（而非工件本身）分配安全标签。四种裁决：`benign executed`（良性）、`harmful blocked`（恶意但被阻断）、`harmful executed`（恶意被执行）、`uncertain`（不确定）。标签依据具体踪迹事件（如文件写入、shell命令、内存更新）给出证据摘要。
  - **知识库与记忆增强**：知识库包含工具分类、风险映射、攻击模式模板、判据清单（类似MITRE ATT&CK）；记忆组件存储先前执行经验（有效触发、误报、漏报等）。两者指导任务生成和证据解释，但不改变基于当前痕迹的最终裁决。

# 7. 优点

- **方法论创新**：将安全审计从静态工件检查转向行为导向的动态探测，通过风险引导的任务生成避免了通用测试的稀疏性和盲目性。
- **上下文感知**：通过准备真实的执行上下文（文件、状态、凭据），暴露依赖环境的恶意分支，弥补静态分析盲区。
- **痕迹驱动的判断**：基于具体踪迹事件（如文件操作、网络请求）作出标签，证据可追溯，且区分“恶意被执行”和“恶意被阻断”，更精细。
- **知识库与记忆**：结构化的安全知识（参考MITRE ATT&CK）和跨技能经验复用增强探查针对性和一致性，且不牺牲判断客观性。
- **鲁棒性验证**：在自进化攻击实验中展示了相对于静态方法显著的优势，证明了动态分析对对抗性修改的抵抗力。

# 8. 不足与局限

- **实验覆盖有限**：仅使用100个OpenClaw技能，数据集规模小，未覆盖其他代理平台（如Claude Code、Codex），外部有效性受限。
- **恶意技能构建**：恶意技能部分来自学术基准（CIK-Bench, Skill-Inject），部分可能为生成式，不完全反映真实攻击者行为的多样性。
- **依赖LLM质量**：配置文件剖析、任务生成、踪迹判断均依赖LLM，其准确性受模型能力、提示设计影响，可能存在偏差或不一致。
- **非穷尽性**：RSA只能检测被生成任务触发的行为，若恶意行为仅在未测试的输入、状态或长时交互中出现，则可能漏检。因此不能证明技能绝对安全。
- **自进化攻击实验**：仅测试了有限轮次和有限变异策略（基于Skill-Inject），可能无法代表更复杂或更定向的逃避技术。

- **未考虑横向比较**：未与黑盒测试、模糊测试等其他动态方法对比，仅与静态基线比较。
