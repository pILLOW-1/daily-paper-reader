## 摘要
LLM智能体越来越依赖于外部推理条件：提示、工具、记忆、标准操作流程（SOP）、技能和框架反馈。这些资产可以在不改变模型权重的情况下改进任务执行，但它们通常通过启发式反思或重用观察到的成功与失败来修订，仿佛单凭计数就是可靠的信念。我们提出了\textbf{Bayesian-Agent}，一个原生且跨框架的框架，将可重复使用的技能和SOP视为关于冻结模型在特定提示、上下文和框架环境下是否会成功的假设。Bayesian-Agent记录已验证的轨迹证据，维护每个技能的特征条件分类后验，并将后验状态映射为可检查的操作，如修补、拆分、压缩、淘汰和探索。面向模型的提示获得可执行的防护栏和故障模式修补，而后验摘要仍可供审计。使用\texttt{deepseek-v4-flash}，增量修复将SOP-Bench从80%提升到95%，Lifelong AgentBench从90%提升到100%，RealFin-Bench从45%提升到65%。我们进一步评估了Bayesian-Agent的原生后端以及可选的GenericAgent、mini-swe-agent和Claude Code后端。结果包括正面、负面、饱和及案例研究设置，表明智能体技能演化最好被视为后验引导的框架优化，而非未校准的提示积累。源代码可在https://github.com/DataArcTech/Bayesian-Agent获取。

## Abstract
LLM agents increasingly rely on external inference conditions: prompts, tools, memory, SOPs, skills, and harness feedback. These assets can improve task execution without changing model weights, but they are often revised by heuristic reflection or by reusing observed successes and failures as if counts alone were reliable belief. We introduce \textbf{Bayesian-Agent}, a native and cross-harness framework that treats reusable skills and SOPs as hypotheses about whether a frozen model will succeed under a particular prompt, context, and harness environment. Bayesian-Agent records verified trajectory evidence, maintains a feature-conditioned categorical posterior over each skill, and maps posterior state into inspectable actions such as patch, split, compress, retire, and explore. Model-facing prompts receive executable guardrails and failure-mode patches, while posterior summaries remain available for audit. With \texttt{deepseek-v4-flash}, incremental repair improves SOP-Bench from 80\% to 95\%, Lifelong AgentBench from 90\% to 100\%, and RealFin-Bench from 45\% to 65\%. We further evaluate Bayesian-Agent's native backend and optional GenericAgent, mini-swe-agent, and Claude Code backends. The results include positive, negative, saturated, and case-study settings, suggesting that agent skill evolution is best viewed as posterior-guided harness optimization rather than uncalibrated prompt accumulation. The source code is available at https://github.com/DataArcTech/Bayesian-Agent.

- **论文立场**：将可复用技能视为承载证据的假设，主张用贝叶斯后验更新代替经验计数，将技能演化从“未校准的提示积累”转变为“后验指导的框架优化”。

## 2. 方法论：核心思想、关键技术细节与算法流程
### 2.1 核心思想
- 将每个技能 \( h_k \) 视为关于冻结模型在给定提示、上下文和框架环境下是否成功的假设。
- 记录已验证的轨迹证据（包括任务输入、技能、上下文、结果、失败模式、成本等），提取离散特征向量，维护特征条件化的分类后验。
- 后验状态映射为五种可检查操作：**探索** (explore)、**修补** (patch)、**拆分** (split)、**压缩** (compress)、**淘汰** (retire)。

### 2.2 关键技术细节
- **证据表示**：每条轨迹 \( e_t = (x_t, h_k, c_t, y_t, u_t, \tau_t, \ell_t, r_t, m_t) \)，其中 \( y_t \) 由外部验证器给出，特征映射 \( g(e_t) \) 将连续量（token数、轮次、延迟）分桶，保留关键失败签名。
- **贝叶斯证据模型**：使用**特征条件化分类后验**。对每个技能 \( h_k \)，维护计数 \( N_{k,\ell} \) 和 \( N_{k,j,\ell,v} \)（特征 \( j \) 取值 \( v \) 时标签 \( \ell \) 的计数）。采用拉普拉斯平滑 (\( \lambda=1 \)) 计算类先验 \( \pi_{k,t}(\ell) \) 和似然 \( \theta_{k,j,t}^{(\ell)}(v) \)。后验成功概率为：
  \[
  \tilde{p}_{k,t}(\ell|z) = \pi_{k,t}(\ell) \prod_{j=1}^m \theta_{k,j,t}^{(\ell)}(z_j) \quad \text{(对数空间计算后归一化)}
  \]
  同时维护 Beta-Bernoulli 摘要 (\( \alpha_{k,t}, \beta_{k,t} \)) 用于兼容性和保守失败检测。
- **后验指导策略**：基于规则的动作决策：
  - **探索**：无观测或后验不确定。
  - **修补**：同一失败模式出现≥2次 → 添加可执行防护栏。
  - **拆分**：≥3个上下文且≥4次观测 → 将笼统技能拆分为更具体版本。
  - **压缩**：≥3次观测且成功概率≥0.72 → 保持简洁。
  - **淘汰**：\( \beta \geq 4 \) 且成功概率<0.45 → 标记为不可靠。
- **模型-框架边界**：智能体提示仅接收可执行的技能文本，后验摘要存储为审计日志。

### 2.3 算法流程
1. 初始化空技能注册表 \( B \)。
2. 若为增量模式，先加载已有基线轨迹，更新后验，仅重跑失败任务。
3. 对每个任务 \( x_t \)：
   - 选择相关技能 \( h_k \)，计算后验状态 \( B_k \)。
   - 根据策略 \( \pi(B_k) \) 决定动作。
   - 渲染模型面向的技能上下文（含防护栏和失败模式补丁）。
   - 保存“之前”快照。
   - 执行框架（native或外部后端）获得结果。
   - 验证结果，构建轨迹，更新后验。
   - 保存“之后”快照和审计记录。

## 6. 主要结论与发现
- **Bayesian-Agent 在增量修复模式下效果最显著**：对 DeepSeek V4-flash，SOP-Bench 从 80% 提升至 95%，Lifelong AgentBench 从 90% 提升至 100%，RealFin-Bench 从 45% 提升至 65%。

- **贝叶斯证据框架提供可审计的演化轨迹**：每次技能修改都有“之前/之后”快照，包括后验审计、模型面向技能文本、信仰文件等，便于调试和审查。
- **与多种后端兼容**：原生 BA、GenericAgent、mini-swe-agent、Claude Code 均可使用同一证据循环。
- **技能演化不是单调的**：存在负例（如 RealFin 中淘汰决定导致后续修复失败）。
- **核心方法论主张成立**：智能体技能演化应被视为后验指导的框架优化，而非未校准的提示积累。
