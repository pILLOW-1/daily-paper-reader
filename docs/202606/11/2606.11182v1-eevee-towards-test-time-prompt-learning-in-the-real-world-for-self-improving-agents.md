## 摘要
本文提出EEVEE，首个面向大语言模型智能体的多数据集测试时提示学习框架，支持在真实世界任务流中进行测试时提示学习。现有方法主要针对单数据集场景设计，而实际应用要求模型处理来自多个数据集、领域和任务分布的异构输入流，限制了其实用性。为减轻跨数据集干扰，EEVEE引入一个路由器，将输入划分到任务簇并分配适当的提示配置。该设计通过路由器-提示协同进化策略进行优化，采用交错的路由器学习和提示学习阶段来解决两者的相互依赖关系。跨多个数据集的实验表明，该框架在异构数据流下提升了鲁棒性，同时保持了单基准学习的能力和效率。具体而言，在Qwen3-4B-Instruct和DeepSeek-V3.2上，EEVEE将平均多基准分数分别提升了10.38和24.32分，超越SOTA方法GEPA和ACE最多37.2%和48.2%。

## Abstract
In this paper, we propose EEVEE, the first multi-dataset test-time prompt learning framework for LLM agents, enabling test-time prompt learning under real-world task streams. Existing methods are largely designed for single-dataset settings, while real-world applications require models to handle heterogeneous input streams drawn from multiple datasets, domains, and task distributions, limiting their practical applicability. To mitigate cross-dataset interference, EEVEE introduces a router that partitions incoming inputs into task clusters and assigns them to suitable prompt configurations. This design is optimized via a router-prompt co-evolution strategy, which employs interleaved router and prompt learning phases to address their mutual dependency. Experiments across multiple datasets demonstrate that the framework improves robustness under heterogeneous data streams while maintaining single-benchmark learning capability and efficiency. Specifically, EEVEE improves average multi-benchmark scores by 10.38 and 24.32 points over Qwen3-4B-Instruct and DeepSeek-V3.2, surpassing SOTA methods GEPA and ACE by up to 37.2% and 48.2%.

# 论文总结：EEVEE: Towards Test-time Prompt Learning in the Real World for Self-Improving Agents

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：现有测试时提示学习（test-time prompt learning）方法（如GEPA、ACE、Combee）主要针对单数据集/单基准场景设计，在真实世界部署中，智能体面临的输入流往往是**多数据集、多领域、多任务分布混合**的异构流。现有方法假设统一的适应目标或固定的提示空间，导致跨数据集干扰（cross-dataset interference）：在一个域上的更新会损害另一个域的性能，累积负保留（negative retention）。
- **整体含义**：本文提出首个面向**多数据集测试时提示学习**的框架EEVEE，通过路由器划分任务簇并分配专用提示，结合路由器-提示协同进化策略，使智能体能够在异构任务流中自我改进，同时保持单基准学习能力和效率。

## 2. 方法论

### 2.1 核心思想

- 维持一组专用提示（prompt set） \(P = \{p_1, \dots, p_K\}\) 和一个路由器（router）\(R\)。路由器根据输入 \(x\) 选择一个提示槽 \(k\)，然后目标模型 \(M\) 使用该提示生成输出：  
  \[
  z = R(x; P) \in \{1,\dots,K\},\quad \hat{y} = M(x; p_z)
  \]
- 路由器与提示相互依赖：路由决定了每个提示学习的样本，提示质量决定了路由决策的好坏。因此需要**路由器-提示协同进化**（router-prompt co-evolution）。

### 2.2 路由器-提示协同进化机制

- **路由器进化（Router Evolve）**：固定提示集，搜索更好的路由器。通过突变（mutation）和反思（reflection）生成候选路由器，使用下游准确率、一致性、平衡性组成的综合分数 \(S_R\) 进行评估，只接受优于阶段基线的路由器。
- **提示进化（Prompt Evolve）**：固定路由器，按路由结果将数据分组，对每个非空槽独立进化。同样使用突变和反思，采用帕累托前沿（Pareto frontier）维护多样化有用提示，并设置空提示阈值避免无效编辑。
- 两者交替执行：路由器进化 → 提示进化 → 下一轮路由器进化（基于更新后的提示集）。

### 2.3 三阶段训练设计

1. **初始化（Initialization）**：在混合训练集上运行提示学习，构建一个多样化的初始提示集，使路由器能观察有用行为差异。通过贪婪覆盖规则选取互补前沿提示。
2. **探索（Exploration）**：从初始 (\(R_0, P_0\)) 开始，在轻量预算下交替路由器和提示进化，采用退火机制从早期偏向多样性逐渐转向后期偏向准确性和稳定性。
3. **收敛（Convergence）**：当路由器稳定后固定 \(R^*\)，重新分配路由数据，以更大预算优化每个槽的提示。

## 6. 主要结论与发现

- **多基准提升显著**：在Qwen3-4B-Instruct上平均分从41.37提升至51.75（+10.38），在DeepSeek-V3.2上从39.75提升至64.07（+24.32），超越GEPA和ACE最多37.2%和48.2%。
- **增量任务保留优势**：随着任务增加，EEVEE保持正累积保留（最终+41.53），而GEPA和ACE降至负值（-15.36和-18.58），证明路由器有效缓解跨数据集干扰。
- **单基准竞争力**：EEVEE在单基准上与其他方法相当，不因路由器设计牺牲单任务性能。
- **Token效率**：EEVEE每样例4.32k tokens，远低于ACE的21.30k，接近GEPA的3.47k。
- **跨模型与跨任务泛化**：学到的提示可迁移至不同模型（Qwen→DeepSeek平均从39.75提升至54.10）；在未见任务上，EEVEE在MBPP上改善，在MMLU-Pro上仅微降（-1.82），优于/等于GEPA和ACE。
- **案例发现**：提示学习最擅长捕获可重用过程（输出格式、代码结构等），但可能弱化领域知识（如GPQA Diamond中的天体物理先验知识）。

## 7. 优点

- **问题新颖**：首次聚焦多数据集异构流测试时提示学习，提出路由器+协同进化解耦思路。
- **方法完整**：三阶段训练（初始化-探索-收敛）设计巧妙，有效处理路由器与提示的相互依赖。
- **实验严谨**：多基准、多模型、多次运行、消融+泛化+成本分析+案例+超参数鲁棒性，全面验证有效性。

- **实用指导**：案例研究揭示提示学习的适用边界（过程vs知识），为部署提供参考。

## 8. 不足与局限

- **仍依赖监督信号**：需要基于ground-truth或规则标签的调整集，并非纯在线/纯反思。
- **分布不匹配风险**：若适应数据噪声大或与真实应用分布不同，学到的提示可能泛化差甚至退化。
- **随机性**：由于随机搜索，不同运行可能得到不同路由器和提示集，无法保证精确复现。
- **模型覆盖有限**：仅在Qwen3-4B-Instruct和DeepSeek-V3.2上验证，未测试更多模型（如GPT-4、Llama系列等）。
- **外部成本**：路由器本身需要额外调用LLM进行突变和反思，训练阶段有一定开销。
- **未讨论完全在线持续学习**：框架仍假设存在准备好的调整数据集，而非持续流入的无限流。
