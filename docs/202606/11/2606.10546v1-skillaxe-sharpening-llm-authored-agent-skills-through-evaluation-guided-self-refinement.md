## 摘要
技能文档是指导大型语言模型（LLM）智能体的结构化自然语言指令，对现代智能体框架至关重要，但LLM难以编写实际可用的技能。在SkillsBench上，人类编写的技能将通过率提高了16.2个百分点，而LLM编写的技能没有带来可衡量的提升。我们提出了SkillAxe，一个完全无监督的框架，使LLM能够迭代地诊断和改进自身技能。SkillAxe将技能质量分解为四个可解释的维度（质量影响、触发精度、指令合规性与故障归因、解决方案路径覆盖），生成结构化的改进简报，无需真实标签、测试套件或环境奖励。在SkillsBench上，与未改进的LLM技能相比，SkillAxe将通过率相对提高了28%，并缩小了与人类编写技能差距的47%-67%。我们在SpreadsheetBench上验证了该方法作为持续改进引擎的实际效果，其中SkillAxe构建的技能库从过去的智能体轨迹中学习，仅用22个技能就将通过率从16.0%提升至52.0%。

## Abstract
Skill documents, structured natural-language instructions that guide Large Language Model (LLM) agents, are critical to modern agent frameworks, yet LLMs struggle to write skills that actually work. On SkillsBench, human-authored skills improve pass rates by 16.2 percentage points, while LLM-authored skills provide no measurable gain. We introduce SkillAxe, a fully unsupervised framework that enables LLMs to iteratively diagnose and refine their own skills. SkillAxe decomposes skill quality into four interpretable dimensions (quality impact, trigger precision, instruction compliance with fault attribution, and solution-path coverage), producing structured improvement briefs that require no ground-truth labels, test suites, or environment rewards. On SkillsBench, SkillAxe improves pass rates by 28\% relative over unimproved LLM skills and closes 47--67\% of the gap to human-authored skills. We validate the approach as a continuous improvement engine in the wild on SpreadsheetBench, where a SkillAxe-built skill library learns from past agent trajectories and raises pass rate from 16.0\% to 52.0\% using only 22 skills.

- **整体含义**：缺乏可操作的诊断反馈是当前技能工程的中心瓶颈。论文旨在构建一个完全无监督的框架，使LLM能够自动诊断并迭代改进自己编写的技能，从而缩小LLM技能与人类技能之间的差距，并支持在生产环境中持续积累和改进技能库。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **SkillAxe** 是一个评估引导的自我改进框架。通过在同一任务上对比智能体**不带技能**和**带技能**的响应行为，计算出四个互补的诊断指标，然后生成结构化改进简报，由LLM据此重写技能。
- 四个诊断维度覆盖技能生命周期的不同故障边界：是否帮助、是否正确触发、智能体是否遵从、技能是否覆盖足够多的执行路径。

### 关键技术细节

1. **质量影响（Quality Impact）**
   - 通过配对比较（带技能 vs 不带技能）评估技能的边际贡献。分两步：
     - 第1步：LLM判断偏好方向 `d ∈ { rs ≻ r0, r0 ≻ rs, tie }`。
     - 第2步：估计改进幅度 `m ∈ [0,1]`，得到综合得分 `Quality = d·m ∈ [-1,1]`。
   - 目的：作为外层循环信号，判断技能整体是否有益，再定位原因。

2. **触发精度（Trigger Precision）**
   - 评估技能是否在正确任务上激活。从技能描述中提取正触发短语 `P^+`（应激活）和负触发短语 `P^-`（不应激活），通过上下文感知嵌入（短语嵌入 + 句子上下文嵌入）在语义空间中定义激活区和排除区。
   - 三个几何诊断：
     - **覆盖广度**：正触发短语的多样性（平均余弦距离）。
     - **负特异性**：负触发短语与最近正触发短语的距离。
     - **边界锐度**：所有正负短语对之间的最小距离。
   - 用于区分触发器过窄、排除不足、边界模糊等故障。

3. **指令合规与故障归因（Instruction Compliance with Fault Attribution）**
   - 将技能分解为可评估的规则，每个规则有严重性权重。LLM对每条规则评估：
     - 相关性 `ρi`、遵循度 `ai`、规则质量 `gi`、技能故障 `fi`（判断失败源于技能还是智能体）。
   - 计算原始遵循度 `Compliance = Σ wi gi ai / Σ wi`，再通过故障调整得到技能信用分数 `SkillScore = Σ wi gi ci / Σ wi`，其中 `ci = ai + (1-ai)(1-fi)`。
   - 关键：区分“智能体没听从好规则”和“规则本身差”，防止错误地修改正确规则。

4. **解决方案路径覆盖（Solution-Path Coverage）**
   - 评估技能是否覆盖任务可能的多种执行策略。LLM枚举 `k` 条合理路径，然后测量技能各块与每条路径的语义对齐度：`PathCoverage = (1/k) Σ_j max_{c∈chunks(s)} cos(e(P_j), e(c))`。
   - 低覆盖意味着技能只支持狭窄行为空间，智能体采用其他有效策略时技能失效。

### 整体流程
- **Phase 1**：对每个任务，智能体不带技能和带技能各运行一次，得到 `r0` 和 `rs`。
- **Phase 2**：计算上述四个诊断指标。
- **Phase 3**：将诊断结果编译成结构化改进简报，LLM据此重写技能。
- **Phase 4**：迭代直到收敛（论文中主要使用单次更新循环）。

## 3. 实验设计

### 数据集/场景
- **SkillsBench**[4]：包含89个任务（实际使用77个），覆盖软件工程、数据科学、科学计算等，每个任务有1-7个技能槽，共191个独特技能。使用Docker容器中的Harbor运行器，智能体骨干为Claude Opus 4.5。
- **SpreadsheetBench**[10]：912个真实世界的电子表格操作任务，具有单元格级黄金答案。分割为200训练/50测试（随机种子42）。智能体为Excel Copilot（基于Claude Opus 4.5）。

### Benchmark与对比方法
- **SkillsBench** 对比四种条件：
  - **No-skill**：裸智能体。
  - **LLM-self**：LLM自写技能（按SkillsBench提示生成）。
  - **SkillAxe**：LLM-self技能经一次SkillAxe循环改进。
  - **Human**：人类编写参考技能。
- **SpreadsheetBench** 对比三种条件：
  - **No skill**：裸Excel Copilot。
  - **LLM-self library**：从训练任务生成69个技能（无改进）。
  - **SkillAxe library**：通过嵌入路由构建的22个技能库，包含两阶段改进。

### 评估协议
- **SkillsBench**：两种评估方式：
  - **本地验证器（native verifier）**：人类编写的pytest套件（Method D评分）。
  - **公平评分器（fair grader）**：LLM judge（GPT-5.4）基于输出文件（图像/文本）判断任务完成情况，不访问测试套件。
- **SpreadsheetBench**：使用原生验证器，通过Excel COM自动重新计算公式缓存后进行单元格级比较。

## 6. 论文的主要结论与发现

1. **SkillAxe显著提升LLM技能效果**：在SkillsBench上，SkillAxe改进后LLM技能通过率相对未改进提升28%（41.6% vs 32.5%），缩小与人类技能差距的47%-67%。

## 7. 优点

- **完全无监督**：无需真实标签、测试套件、环境奖励，仅需任务指令和智能体输出，适用于生产环境。
- **可解释的多维诊断**：四个维度对应不同故障模式，诊断结果直接指导针对性的重写动作，避免盲目修改。
- **故障归因清晰**：区分“技能本身差”和“智能体没执行好”，防止错误地修改正确规则。
- **跨任务泛化**：在SkillsBench（通用任务）和SpreadsheetBench（电子表格）上均验证有效，且后者展示了从历史轨迹持续积累库的能力。
- **效率优势**：通过路由合并相似任务，以更少技能达到同等或更好效果，降低延迟和令牌成本。
- **实验设计考虑充分**：使用双评估协议、层次分解、统计分析，增加结论可信度。

## 8. 不足与局限

1. **无法检测结构性策略错误**：如果技能整体策略完全错误但内部自洽，规则级评估可能无法发现问题（无规则违反，但策略无效）。
2. **忽略多技能交互**：当前每个技能独立评估和改进，未建模多个技能同时激活时的相互冲突或协作效果。
3. **依赖LLM判断的偏差**：合规评估和公平评分均使用LLM judge，可能存在位置偏差、校准偏差或对特定模式的偏见。
4. **单次更新循环可能不足**：实验中仅执行一次改进迭代，剩余与人类技能的差距可能需要多轮循环和更强的在线执行反馈。
5. **实验规模有限**：SkillsBench每条件仅2次运行；SpreadsheetBench测试集仅50个任务；仅使用一种LLM骨干（Claude Opus 4.5），未测试其他模型（如GPT-4）。
6. **触发评估依赖嵌入质量**：使用MiniLM-L6-v2作为嵌入模型，不同嵌入模型可能影响诊断结果，未进行嵌入敏感性分析。
7. **未探讨安全性**：自动改进的技能可能传播错误指导，在高风险场景下需要人工审核，论文建议但未提供自动化安全机制。
