## 摘要
推荐算法迭代正从一种手工的、依赖工程师的过程转向工业化的研究循环，但这一转型仍受到结构性执行瓶颈的阻碍：从想法到上线的周期仍然依赖人类工程师来生成假设、修改生产代码、启动A/B实验以及归因线上结果。因此，创新与人员数量呈线性增长，而非与证据、计算资源和累积的实验知识复合增长。我们提出AgentX，一个生产部署的多智能体系统，从根本上重构了这一生产函数。AgentX作为一个自我进化的开发引擎运行：它自主地生成、实现、评估并从推荐实验中学习，其规模和速度是任何人工工作流都无法维持的。

该系统在一个闭环中协调四个紧密耦合的阶段。灵感生成智能体综合来自历史实验、系统架构、数据分析和外部研究的证据，生成排序后的可执行提案。开发智能体通过基于仓库的生成和多维可靠性验证，将每个提案转化为生产就绪的代码。评估智能体通过带护栏否决的A/B判断进行安全在线部署，将成功和失败都转化为结构化的知识资产。然后，一个驾驭进化层（SGPO）将执行轨迹提炼为语义梯度更新，不断优化智能体本身——使系统不仅仅是自动化，而且能够自我改进。

## Abstract
Recommendation algorithm iteration is moving from an artisanal, engineer-bound process toward an industrialized research loop, but this transition remains blocked by a structural execution bottleneck: the idea-to-launch cycle still depends on human engineers to generate hypotheses, modify production code, launch A/B experiments, and attribute online results. Innovation therefore scales linearly with headcount rather than compounding with evidence, compute, and accumulated experimental knowledge. We present AgentX, a production-deployed multi-agent system that fundamentally restructures this production function. AgentX operates as a self-evolving development engine: it autonomously generates, implements, evaluates, and learns from recommendation experiments at a scale and pace that no manual workflow can sustain.   The system orchestrates four tightly coupled stages in a closed loop. A Brainstorm Agent synthesizes evidence from historical experiments, system architecture, data analysis, and external research into ranked, executable proposals. A Developing Agent translates each proposal into production-ready code through repository-grounded generation and multi-dimensional reliability verification. An Evaluation Agent conducts safe online rollout with guardrail-vetoed A/B judgment, converting both successes and failures into structured knowledge assets. A Harness Evolution layer (SGPO) then distills execution trajectories into semantic-gradient updates that continuously sharpen the agents themselves -- making the system not merely automated, but self-improving.

## 2. 论文提出的方法论

### 核心思想
- 构建一个四阶段闭环多智能体系统：**Brainstorm Agent → Developing Agent → Evaluation Agent → Harness Evolution**。
- 三个阶段完成一次“想法→上线”的完整迭代，第四阶段利用积累的执行轨迹优化前三阶段智能体的提示（prompt）、验证规则和工具使用习惯，实现系统自我进化。

### 关键技术细节

#### （1）Brainstorm Agent（灵感生成智能体）
- **输入**：模糊的优化意图（如“提升用户观看时长”）。
- **流程**：
  1. **任务边界规范化**：将意图转化为明确的业务领域、目标指标、禁止修改范围等。
  2. **有界探索**：分批生成候选想法（每批不超过5个），并按成熟度分为“准备实施”“需先探测”“远期储备”三类。
  3. **证据加权生成**：从四个知识源（实验知识库 Experiment KB、系统知识库 System KB、数据分析 Data Analysis、模型研究 Model Research）检索证据，并动态分配权重，计算每个想法的综合得分：
     - `S(c|q) = λ_o O(c,q) + λ_b B(c) + λ_f F(c) + λ_h H(c) + λ_e E(c|q) - λ_r R(c)`
     - 其中 `O` 为目标对齐度，`B` 为业务语义有效性，`F` 为实现可行性，`H` 为交接完备度，`E` 为加权证据得分，`R` 为风险惩罚。
  4. **验证与交接**：通过审核（含人工审查）后生成结构化提案，传递给开发智能体。

#### （2）Developing Agent（开发智能体）
- **两条并行轨道**：
  - **线上策略轨道**（Online Strategy Developing）：将提案转化为生产代码变更。
    - **仓库接地生成**：强制使用模式库和案例工具箱（schema 查询工具、DSL 检查器、C++ 语法检查器），避免属性幻觉（attribute hallucination）和注册模式遗漏。
    - **验证导向实现循环**：分阶段实现，通过准确率循环（accuracy loop）和干运行（dryrun）管道验证，失败时给出定向修复指令。
    - **质量评分**：8 维度加权评分（`Q_code`），其中属性幻觉、正确性循环次数、人为干预占比 58%，直接威胁自主生产可靠性。
  - **离线模型轨道**（Model Developing）：将模型架构提案转化为可信任的训练实验。
    - **单轮管道**：策略声明（含因果机制和预期可观测量）→ 代码实现与验证（最多 3 次重写）→ 独立专家投票（超级多数共识，≥⌈2N/3⌉）→ 纯 Python 状态机执行训练 → 最终审核。
    - **可证伪归因**：严格检查声明因果关系链的每一环是否在训练日志中得到验证（verified/broken/unclear），只有全部 verified 才标记为 CLEAR，否则即使 AUC 提升也不记录为成功。
    - **平台故障鲁棒执行**：分类失败原因（确定性错误直接放弃，瞬态故障重试一次），由看门狗守护进程自动处理，无需人工介入。

#### （3）Evaluation Agent（评估智能体）
- **安全部署**：通过 OpenAPI 进行灰度配置，检查参数白名单，确保不与已有实验冲突。
- **A/B 判断与护栏否决**：
  - 使用方差缩减方法（CUPED、DiD 或直接分组对比）提取指标。
  - 护栏采用三层设计：硬拦截（严重恶化）→ 升级审查（中等信号）→ 仅监视。
  - 每个业务域自有护栏指标，复合经济交换得分（LT）而非单指标否决。
  - 输出结构化判决：KEEP / EXTEND / DISCARD。
- **负结果资产化**：每个失败的实验记录根本原因（显著性不足、护栏恶化、流量不匹配等），并索引到知识库，避免未来重复相同方向。

#### （4）Harness Evolution（驾驭进化）
- **SGPO-I（基于对话轨迹的语义梯度提示优化）**：
  - 从在线轨迹池中采样与目标子智能体相关的轨迹，提取评估模板（rubrics）。
  - 评估智能体生成自然语言损失报告和语义梯度（`g_t,i`），指出缺失约束、步骤顺序不当等。
  - 精炼智能体将梯度转换为局部提示编辑，生成候选项 `h'_t,i`。
  - 通过配对重放（paired replay）比较新旧驾驭在相同任务上的得分，只接受 `ΔJ > ε` 且通过安全检查的更新。
  - 在灵感生成智能体上应用 5 轮进化，标准化重放得分从 75.15% 提升至 98.00%。
- **SGPO-II（基于编码重放案例的变体）**：
  - 证据来源改为历史合并请求（MR），过滤后作为要求复现任务（隐藏原始补丁）。
  - 评估维度：语义正确性（40%，硬门限 ≥4）、需求覆盖度（25%）、文件覆盖度（20%）、安全默认（10%）、代码风格（5%）。
  - 案例显示在复杂异步模块上得分从 2.60 提升至 4.90（+88%）。
- **模型研究探索管道进化**：
  - 三阶段循环：单论文复现（Phase 1）→ 模块消融（Phase 2，每个模块在 32 次实验中至少 24 次正收益才确认有效）→ 跨论文组合（Phase 3，每 4 轮加上挑战轮以维持多样性）。
  - 记忆引导剪枝：论文级剪枝（核心前提被证伪）、模块级剪枝（无独立贡献）、饱和度终止（新颖性签名重复率>80% 连续两轮）。
  - 经验飞轮：只有通过阈值门限（至少两次独立运行）和对抗审查（专用智能体试图证伪因果机制）的经验才被注入后续环节。

3. **在线收益显著**：主 feed 用户使用时长提升 0.561%，生活服务年化收入超过 1 亿元人民币。
4. **模型研究探索有效**：AgentX 能自动复现多篇论文，发现有效的模块组合（如 MHFT + VQ_Code + MVSF 在 KuaiRand 和 Taobao 上平均提升 +0.0264 AUC），且工业场景验证与公开数据一致。
5. **闭环瓶颈在于操作与基础设施，而非智能体推理**：91.4% 的灵感被拒绝是由于参数资源冲突、前置开关未开等平台限制；编码失败中 70% 是 DSL/框架语法错误。提示未来改进方向应聚焦于上游冲突检测和模板化。

## 7. 优点

- **真实在线奖励**：将线上 A/B 结果作为权威信号，而非离线指标或模拟评价，使优化目标与业务价值对齐。
- **完整闭环**：覆盖从模糊意图到上线部署的全生命周期，无需人工拼接各环节。
- **自我进化**：SGPO 利用执行轨迹优化智能体自身，使系统能力随时间复合增长，而非一次性的自动化工具。
- **模块化设计**：各智能体职责清晰（Brainstorm、Developing、Evaluation、Harness Evolution），便于独立维护和演进。
- **知识累积**：实验成功与失败均结构化为知识库条目，避免重复错误，支持长期智能增长。
- **机器人格鲁夫**：SGPO 通过配对重放严格门限，确保进化安全性，避免 regressive changes 进入生产。

## 8. 不足与局限

- **实验覆盖的局限性**：
  - 生产实验只在一个平台（快手）的两个场景进行三周，泛化性未知。
  - 公共数据集实验规模较小（百万级用户），未在更大规模（十亿级）公开 benchmark 如 Criteo 上验证。
  - 对比仅针对单个工程师，未与其他同类自动化系统比较。
- **资源与算力未透明**：缺乏 GPU 型号、训练时长、LLM 模型规格等细节，限制可复现性和成本评估。
- **依赖高质量知识库**：System KB、Experiment KB 等需要持续维护，初始构建成本高；若知识库不完整或不准确，可能误导智能体。
- **护栏可能过度保守**：尽管设计为三级，但生产实验中 64.7% 的驳回源于参数资源冲突（平台约束），说明护栏或实验管理系统本身造成了大量浪费。
- **无法保证完全脱离人类**：关键节点（如灵感选择、灰度权限）仍需要人工审核；人类工程师角色从执行转向决策和系统演进。
- **跨数据集迁移不一致**：公共数据上的排名与工业数据不完全一致，说明探索结果需在目标环境重新验证。
- **SGPO 的非单调性**：语义梯度可能误诊导致后退（如出现一次 -1.87 的分数下降），虽然配对重放门限阻止了坏更新，但说明评估智能体不是完美的。
