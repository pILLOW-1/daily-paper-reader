## 摘要
多模态大语言模型（MLLMs）极大地推动了移动代理的发展，然而主动移动辅助仍然具有挑战性，因为代理必须在决定*如何*协助之前先判断*何时*进行干预。现有系统通常将这两个决策统一实现在基于MLLM的流水线中，导致保守的干预过滤与全面的辅助生成之间的目标不一致，以及在代理应保持沉默时的冗余推理。为了解决这些局限性，我们提出了**预推理感知框架（PRPF）**，这是一个建立在先感知后推理基础上的两阶段框架。PRPF引入了一个轻量级的多模态主动感知器（MPP）用于干预门控和上下文压缩，并仅在需要干预时激活主动代理推理器（PAR）。在ProactiveMobile基准上的实验表明，与ProactiveMobile基线相比，PRPF显著降低了误触发率（FTR），同时提高了成功率（SR）和推理效率。

## Abstract
Multimodal large language models (MLLMs) have substantially advanced mobile agents, yet proactive mobile assistance remains challenging because agents must decide \emph{when} to intervene before determining \emph{how} to assist. Existing systems often implement these two decisions within a unified MLLM-based pipeline, leading to goal misalignment between conservative intervention filtering and comprehensive assistance generation, as well as redundant inference when the agent should remain silent. To address these limitations, we propose the \textbf{Pre-Reasoning Perception Framework (PRPF)}, a two-stage framework built on perceiving before reasoning. PRPF introduces a lightweight Multimodal Proactive Perceptor (MPP) for intervention gating and context compression, and activates the Proactive Agent Reasoner (PAR) only when intervention is warranted. Experiments on the ProactiveMobile benchmark show that PRPF substantially reduces false trigger rates (FTR) while improving success rates (SR) and inference efficiency over the ProactiveMobile baseline.

## 论文总结：Perceive Before Reasoning

### 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现有的主动式移动智能体（Proactive Mobile Agents）在提供协助时，面临两个核心挑战：
    1.  **目标冲突（Goal Misalignment）**：系统需要同时做出“何时干预”的保守判断和“如何协助”的生成式推理。将这两个目标耦合在一个统一的MLLM管线中，难以同时实现低误触发率和高协助质量。
    2.  **推理低效（Inference Inefficiency）**：无论当前是否需要干预，系统都会执行完整的、昂贵的大模型推理。在大多数无干预需求的场景下，这造成了巨大的算力浪费和用户干扰。
- **研究动机**：为了解决上述问题，论文提出将“何时干预”和“如何协助”这两个决策进行**架构级别的解耦**。核心思想是：**先进行轻量级的感知和判断，只有在必要时才启动重量级的推理**。

### 2. 论文提出的方法论

- **核心思想**：提出**预推理感知框架（PRPF, Pre-Reasoning Perception Framework）**，遵循“先感知，后推理”的原则，将过程分为两个明确的阶段。
- **关键技术与流程**：
    1.  **第一阶段：轻量级感知与门控 (MPP, Multimodal Proactive Perceptor)**
        - **功能**：一个轻量级的多模态融合编码器（约0.1B参数），负责**干预门控（Intervention Gating）**和**上下文压缩（Context Compression）**。
        - **技术细节**：
            - **双通道交互模块**：包含一个处理长周期行为偏好的**慢通道（Slow Channel）**和一个捕捉短周期界面动态的**快通道（Fast Channel）**。
            - **交叉注意力机制**：让快慢通道的信息相互增强。
            - **输出**：
                - **干预门控头（Trigger-gating Head）**：输出是否需要干预的概率 (`ptrig`)。如果概率低于阈值 (`τ`)，则直接过滤，不触发下一阶段。
                - **函数场景预测头（Function-scenario Prediction Head）**：输出候选函数场景的概率，选择概率最高的Top-K个场景，将候选函数集从原来的63个压缩到不超过20个，减少下游推理的负担。
    2.  **第二阶段：推理与生成 (PAR, Proactive Agent Reasoner)**
        - **功能**：一个基于大型MLLM的推理器（如Qwen3.5-9B），**仅在MPP判定需要干预时才被激活**，进行最终的、聚焦的推理。
        - **推理流程**：生成的推理链依次包括：
            1.  **UI摘要（ui_summary）**：描述当前用户界面内容和操作阶段。
            2.  **思考链（thinking）**：分析用户行为、意图和是否需要推荐，包含函数选择过程 (`function_selection`)。
            3.  **推荐结果（recommendations）**：输出结构化的推荐指令和函数调用。
        - **训练**：PAR首先通过监督微调（SFT）学习输出结构，然后使用**GRPO强化学习**优化其在边界案例上的决策和函数选择，提升鲁棒性。

- **创新的两阶段解耦架构**：PRPF的核心贡献在于从架构层面分离了“何时”和“如何”两个决策，从根本上解决了此前单阶段模型的目标冲突和效率问题。这是非常实用和有洞察力的设计。
