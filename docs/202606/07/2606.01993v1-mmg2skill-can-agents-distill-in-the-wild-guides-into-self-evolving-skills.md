## 摘要
网络上丰富的程序性知识对于帮助代理解决长期任务具有巨大潜力。然而，这些知识通常是多模态、异构、嘈杂的，并且隐含地假设了人类执行者，因此难以直接用作代理所需的技能。为了弥合面向人类的指南与代理可执行技能之间的差距，我们将此问题形式化为指南到技能学习：将野外指南转化为可执行技能，并从代理可观测的轨迹中持续改进这些技能。为了评估现有代理在此任务上的能力，我们引入了MMG2Skill-Bench，这是为此问题设计的首个基准测试。我们进一步提出了MMG2Skill，一个闭环框架，它将指南编译为可编辑的技能，在执行过程中将这些技能作为条件输入给固定的视觉语言模型（VLM）代理，并从轨迹级别的根本原因反馈中修正技能，而不使用基准分数。在GUI控制、开放结局游戏和策略卡牌游戏中，使用六种VLM骨干网络，MMG2Skill在每个模型-领域设置中始终优于原始基线代理，跨骨干网络的宏观平均增益为+12.8至+25.3个百分点。消融研究表明，直接用原始指南提示代理可能会降低性能，而结构化的技能构建和轨迹驱动的修正对于观察到的改进都是必要的。在可推断成功的任务中，基于分析器的提前停止进一步防止了后期性能退化，并且在成功信号正确校准的情况下节省了25%-53%的尝试次数。

## Abstract
Abundant procedural knowledge on the Web holds great potential for helping agents solve long-horizon tasks. However, such knowledge is often multimodal, heterogeneous, noisy, and implicitly assumes human executors, making it difficult to use directly as the skills required by agents. To bridge the gap between human-oriented guides and agent-executable skills, we formalize this problem as guide-to-skill learning: converting in-the-wild guides into executable skills and continuously improving them from trajectories observable to the agent. To evaluate the capability of existing agents on this task, we introduce MMG2Skill-Bench, the first benchmark designed for this problem. We further propose MMG2Skill, a closed-loop framework that compiles guides into editable skills, conditions a fixed vision-language model (VLM) agent on these skills during execution, and revises the skills from trajectory-level root-cause feedback without using benchmark scores. Across GUI control, open-ended gameplay, and strategic card play with six VLM backbones, MMG2Skill consistently outperforms vanilla baseline agents in every model-domain setting, achieving macro-average gains of +12.8 to +25.3 percentage points across backbones. Ablation studies show that directly prompting agents with raw guides can degrade performance, while both structured skill construction and trajectory-driven revision are necessary for the observed improvements. On success-inferable tasks, analyzer-based early stopping further prevents late-stage performance regressions and saves 25%-53% of attempts when the success signal is properly calibrated.

## 2. 论文提出的方法论

### 核心思想：闭环技能蒸馏与修订框架 MMG2Skill

形式化目标：寻找在固定VLM策略 πₜₕₑₜₐ 下最大化期望得分的技能集 S* ∈ Ω(G)（G为指南），优化变量仅为可编辑的技能表示。

### 关键技术细节（三阶段闭环循环）

1. **阶段1：多模态技能构建（Construct Skills）**  
   - 将多模态指南（HTML+图片）转化为结构化、可编辑的 `SKILL.md` 表示，每个技能 z_i = (u_i, c_i, v_i, q_i)，分别表示可重用过程、适用条件、期望状态线索、恢复知识。
   - 使用VLM提取器一次性构建初始技能集 S1。

2. **阶段2：技能条件化执行（Skill-Conditioned Execution）**  
   - 在每一步，当前技能集 Sk 被注入到智能体上下文，与任务指令和历史轨迹一起条件化产生动作：aₜ ∼ πₜₕₑₜₐ(aₜ | hₜ, I, Sk)。智能体本身固定不更新。

3. **阶段3：技能修订循环（Analyzer + Refiner）**  
   - **分析器（Analyzer）**：读取任务指令和智能体可见轨迹（无基准分数），生成诊断ρₖ = (eₖ, rₖ)，包括轨迹证据eₖ和结果评估rₖ（likely_success / uncertain / likely_failure）。长轨迹被分块处理。
   - **精炼器（Refiner）**：基于原始指南G、当前技能Sk、以及累积的所有历史诊断ρ₁:k，对技能集进行本地编辑（添加缺失检查、强化证据、澄清线索等），确保已修复行为不被后续覆盖。
   - **早停机制**：当分析器输出 likely_success 时，停止循环并返回当前技能和轨迹；否则持续修订达到预算N（默认5次）。

### 伪算法流程（Algorithm 1）

```
S1 ← ConstructSkills(G, I)
for k = 1 to N:
    τk ← Execute(I, Sk)
    ρk = (ek, rk) ← Analyze(I, τk)
    if rk == likely_success: return Sk, τk
    Sk+1 ← Refine(G, I, Sk, ρ1:k)
return SN, τN
```

## 3. 实验设计

### 基准与场景：MMG2Skill-Bench

- **三大交互领域，130个可推断成功的任务**：
  - **MMG2Skill-GUI**：基于 OSWorld，40个桌面应用任务（LibreOffice, VS Code, Chrome等），使用PyAutoGUI动作。
  - **MMG2Skill-Game**：基于 Minecraft (OpenHA + MineStudio)，30个开放世界任务（采矿、合成、冶炼），探索/采集/合成过程。
  - **MMG2Skill-Strategy**：基于 RLCard，60个策略卡牌任务（30个斗地主 + 30个麻将），回合制决策，对手为固定训练的DMC/NFSP策略。

- **指南语料**：
  - 每个任务对应1~5个公开人类编写指南（HTML+图片），如桌面软件文档、Minecraft Wiki、卡牌策略指南。指南不包含基准解或隐藏标签，排除可直接复制答案的任务。

- **对比方法**：
  - **Vanilla（基线）**：同一VLM智能体，不使用外部技能。
  - **Raw Guide**：直接将原始指南注入提示，无技能构建和修订。
  - **MMG2Skill**（主方法）：使用技能构建+修订闭环，早停策略。

- **VLM骨干**：六种前沿模型——Claude-Opus-4.6, GPT-5.5, Claude-Sonnet-4.6, Kimi-K2.6, Gemini-3.1-Pro-Preview, Qwen3.6-Plus。同一个模型同时用于技能构建、执行、分析和修订（无更强评判模型）。

## 6. 论文的主要结论与发现

1. **公共指南含有程序知识，但原始提示可靠性差**：Raw Guide在GUI上持平，在Game和Strategy上甚至下降（-1.67 pp），原因是指南与环境之间存在接地不匹配。
2. **技能构建提供更安全的程序先验**：即使不修订，仅技能构建（w/o revision）已在所有领域匹配或超过Vanilla。
3. **轨迹驱动的修订是核心增益来源**：在Game和Strategy领域，修订贡献了超过90%的总增益；修正的是运行时接地差（如缺失的验证步骤、非明显配方）。
4. **增益非单调，早停至关重要**：全集视图（取最后一次尝试）在Game和Strategy上可能倒退（如Game从66.1%降至47.8%），而早停视图持续提升并避免回归。
5. **分析器信号在成功可推断任务上校准良好**：likely_success 在GUI/Game/Strategy斗地主上精度>74%，召回>93%；在麻将上精度71%、召回49.5%，表明部分任务仍难以通过轨迹推断成功。在私域Hold'em上完全失效（精度9.9%）。
6. **早停节省大量尝试**：节省25%-53%的尝试次数，对应23%-42%的API调用节省。
7. **失败模式依赖于领域**：GUI失败常涉及屏幕接地与分析器误差耦合；Game失败主要是执行脆弱性（预算耗尽、接地错误）；Strategy失败源于决策规则转化困难（错误做法、策略循环）。

## 7. 优点

- **问题形式化新颖**：首次定义“指南到技能学习”，提供基准和框架，弥合了人类指南与智能体技能之间的鸿沟。
- **基准MMG2Skill-Bench设计合理**：跨三个差异巨大的领域，任务均为成功可推断，指南为公共人类材料，排除了答案直接复制的泄漏。
- **框架MMG2Skill闭环自改进**：利用同一VLM进行所有组件（构建、执行、分析、修订），无需外部奖励或基准分数，仅从智能体可见轨迹获取反馈。编辑技能比累积上下文更有效。
- **早停机制实用且有效**：基于分析器的成功判断不仅避免了后期性能退化，还显著节省环境交互和API成本。文中详细校准了信号并展示了边界条件（私域任务需另处理）。
- **充分的消融与诊断**：不仅报告主结果，还逐步解构增益来源（技能提取vs修订），分析失败归因，展示不同模型的修订动力学，以及多运行稳定性。
- **实验覆盖全面**：6个VLM骨干、130个任务、多个对照条件，统计检验支持结论可靠性。

## 8. 不足与局限

- **缺乏指南发现环节**：当前假设任务已提供相关指南，未涉及如何从海量网络中自动搜索、过滤、排序最佳指南。指南质量可能影响结果，修订仅能部分修复错误指南。
- **成本高**：需要多次VLM API调用（构建+执行步骤+分析+修订），商业模型账单可能昂贵；论文未提供单次任务的明确定价。
- **仅限成功可推断任务**：主基准排除结局依赖于隐藏状态的游戏（如扑克），实际部署中很多任务不可推断成功，那时分析器早停不可靠。
- **评估速度慢**：交互式环境（GUI, Minecraft）需要顺序执行，受限于API速率和模拟器速度，扩展难度大。
- **模型选择有限**：仅测试闭源/半开源商业模型，未包括开源可本地部署模型（如Llama系列），也未测试不同规模的VLM（如3B vs 70B）。
- **超参数不够深入**：尝试预算N=5选择来自经验，对于更复杂任务可能需要更多次修订；分析器分块大小未做系统搜索。
- **失败归因主观性**：图6的错误标签由作者人工标注，可能存在歧义或主观偏差。
- **没有与更强的基线对比**：如Reflexion（带追加根因上下文的反思）仅在附录中初步对比（kimi和qwen上落后），但未作为正式基线。
- **未探索技能迁移**：技能是任务特定的，未研究同一技能是否可跨任务复用；指南通常包含比单任务更广的知识。
