## 摘要
基于LLM的自进化智能体主要通过改变其智能体框架（即围绕基础模型的结构化执行层，包括提示、记忆、工具、中间件、运行时状态以及模型-工具交互循环）来改进。现有的评估通常将此过程简化为孤立的任务分数或单一的顺序曲线，掩盖了更新是否产生可复用的改进、是否过拟合近期任务、是否增加成本或损害旧有行为。我们引入了SEAGym，这是一个用于测量智能体框架更新跨训练、验证、测试、回放和成本记录的评估环境。SEAGym将兼容Harbor的基准测试转化为动态的自进化任务源，包含训练批次、冻结更新验证、保留的同分布和跨分布迁移视图、回放诊断以及保存的快照和指标记录。在Terminal-Bench 2.0和HLE上实例化SEAGym后，我们比较了ACE、TF-GRPO和AHE在共享轮次/批次协议下的表现。结果表明，这些评估视图提供了关于进化过程的互补信号：频繁更新可能无法提升保留性能，有用的中间快照可能在后期崩溃，并且来源多样性和模型后端可能影响框架的可靠性。

## Abstract
Self-evolving LLM-based agents improve mainly by changing their agent harness: the structured execution layer around a base model, including prompts, memory, tools, middleware, runtime state, and the model-tool interaction loop. Existing evaluations often reduce this process to isolated task scores or a single sequential curve, obscuring whether an update produces reusable improvement, overfits recent tasks, increases cost, or harms older behavior. We introduce SEAGym, an evaluation environment for measuring agent harness updates across training, validation, test, replay, and cost records. SEAGym turns Harbor-compatible benchmarks into dynamic self-evolution task sources with train batches, frozen update-validation, held-out ID and OOD transfer views, replay diagnostics, and saved snapshot and metric records. Instantiating SEAGym on Terminal-Bench 2.0 and HLE, we compare ACE, TF-GRPO, and AHE under a shared epoch/batch protocol. The results show that these evaluation views provide complementary signals about the evolution process: frequent updates may fail to improve held-out performance, useful intermediate snapshots may collapse later, and source diversity and model backend can affect harness reliability.

## 6. 主要结论与发现

1. **不同方法的演化机制各异**：
   - **AHE**：直接编辑框架，可同时改善验证、ID和OOD，但可编辑范围大也带来可靠性风险（中间快照可能因运行时消息契约错误而崩溃）。
   - **ACE**：积累可复用的过程知识（技能书），提升有限，对运行时行为或环境交互失败的改善力弱。
   - **TF-GRPO**：针对特定任务家族积累具体经验，产生强源验证增益，但OOD下降且成本最高。

2. **验证增益并不保证迁移**：更新在验证集上提升，未必能改善ID或OOD；例如TF-GRPO验证增益大但OOD下降。

3. **有用中间快照可能后期崩溃**：AHE在E16出现大规模运行时消息契约错误，但最终恢复，说明最终分数掩盖了危险的中间状态。

4. **批次大小非单调**：batch20效果最好，小批次（10）频繁更新积累配置风险，大批次（80）证据过载导致全局模式主导、长尾故障被稀释。

5. **源多样性影响可靠性**：混合源暴露多种失败模式（工具、环境、推理），有助于最终恢复；HLE-only训练集中在验证子系统，最终因运行时接口错误全面崩溃。

6. **跨模型迁移不对称**：同一后端演化的框架对对侧ID增益不稳定，OOD增益普遍较弱或为负，说明框架编辑与评估轨迹的失败模式高度耦合。

7. **重放诊断揭示任务级变动**：最终快照修复了13个初始失败任务，但忘记了4个初始成功任务；中间运行时错误（E16）并非普通遗忘，而是执行路径破坏。

## 7. 优点

1. **方法论创新**：将自进化评估从单一分数扩展为多视角、动态的过程分析，填补了现有基准（静态评测或流式评测）的不足。
2. **统一框架**：通过调度参数兼容在线、单任务、批量、轮次等多种演化模式，无需为每种模式重新设计基准。
3. **可扩展性**：基于Harbor执行框架，可复用已有Harbor兼容基准；rollout/update接口分离使新方法易于集成。
4. **诊断能力**：保存详细的轨迹、更新摘要、框架差异和快照，支持离线分析退化原因（如运行时契约错误），而不仅是分数下降。
5. **实验设计严谨**：从批次大小、源多样性、跨模型迁移等多个角度消融，揭示演化机制而非仅排名。
6. **成本可见性**：报告token消耗、更新次数等成本指标，帮助评估效率-收益权衡。

## 8. 不足与局限

1. **领域覆盖有限**：仅在Terminal-Bench 2.0和HLE两个基准上实例化，尚未在Web交互、桌面操作、多智能体协作等更大范围验证。
2. **缺乏统计重复**：每组实验仅报告单次运行结果，未提供多次运行的均值和置信区间，难以评估实验稳定性。
