## 摘要
AI agent的性能关键依赖于运行时框架（harness），包括提示、工具、记忆以及控制流，它们调节模型如何观察、推理和行动。然而，如今的运行时框架大多仍为手工构建且静态：每个新模型或新任务仍需要定制化的脚手架，而执行过程中产生的丰富轨迹很少被提炼为系统性改进。我们引入HarnessX，一个用于可组合、自适应和可演化agent运行时框架的工坊。HarnessX通过替换代数组装类型化的运行时原语，通过AEGIS（一个基于符号适应与强化学习之间操作镜像的轨迹驱动多智能体演化引擎）对其进行适应，并通过将轨迹转换为运行时更新和模型训练信号来闭合运行时-模型循环。在五个基准测试（ALFWorld、GAIA、WebShop、tau^3-Bench和SWE-bench Verified）上，HarnessX平均提升+14.5%（最高+44.0%），其中基线最低的场景提升最大。这些结果表明，agent的进步不必仅来自模型规模的扩展：从执行反馈中组合和演化运行时接口是一个可行且互补的杠杆。完整的代码库将在未来版本中开源。

## Abstract
AI agent performance depends critically on the runtime harness, comprising the prompts, tools, memory, and control flow that mediate how a model observes, reasons, and acts. Yet today's harnesses remain largely hand-crafted and static: each new model or task still demands bespoke scaffolding, and the rich traces produced during execution are rarely distilled back into systematic improvement. We introduce HarnessX, a foundry for composable, adaptive, and evolvable agent harnesses. HarnessX assembles typed harness primitives via a substitution algebra, adapts them through AEGIS, a trace-driven multi-agent evolution engine grounded in an operational mirror between symbolic adaptation and reinforcement learning, and closes the harness-model loop by turning trajectories into both harness updates and model training signal. Across five benchmarks (ALFWorld, GAIA, WebShop, tau^3-Bench, and SWE-bench Verified), HarnessX yields an average gain of +14.5% (up to +44.0%), with gains largest where baselines are lowest. These results suggest that agent progress need not come from model scaling alone: composing and evolving runtime interfaces from execution feedback is an actionable and complementary lever. The complete codebase will be open-sourced in a future release.

## 1. 核心问题与研究动机

当前AI智能体的性能严重依赖其**运行时框架（harness）**——包括提示（prompt）、工具（tools）、记忆（memory）和控制流（control flow）。然而，现有的harness普遍存在三大问题：
- **手工构建且静态**：每当模型版本、工具或任务域变化时，都需要人工重新定制，缺乏经验驱动的自动改进机制。
- **架构耦合严重**：提示模板、工具包装、重试策略和记忆等组件混在相同的代码路径中，修改一个组件可能静默破坏其他部分，跨域复用只能靠复制粘贴。
- **框架工程与模型训练割裂**：执行轨迹数据在框架改进后通常被抛弃，没有反馈到模型训练中；模型改进也不会自动转化为框架改进。

论文的核心论点：**智能体进步不必仅依赖模型规模扩展，从执行反馈中组合和演化运行时接口是一个可行且互补的杠杆。** 提出 HarnessX，一个将harness视为**一等对象**的工坊，支持可组合、自适应和与模型协同演化。

## 2. 方法论：核心思想与关键技术

HarnessX 包含三个相互交织的层次：

### 2.1 框架组合（Harness Composition）
- **Harness 作为一等对象**：定义为 H = (M, C)，其中 M 是模型配置（哪个模型扮演哪个角色），C 是框架配置。框架配置 C = (P, S)，P 是生命周期的钩子（hook）上挂载的处理器列表（8个钩子事件，如task_start、step_start等），S 是正交的槽位资源（工具注册表、追踪器、工作区等）。
- **处理器抽象**：每个行为实现为一个异步处理器 `process(event) -> AsyncIterator[Event]`，可产生通过、转换、分裂、拦截或中断五种结果。处理器通过钩子约束、单例组（singleton_group）、顺序提示（order）和软依赖（after）保证组合的类型安全。
- **九维分类法**：将行为空间组织为9个正交维度：模型选择、上下文组装、记忆管理、工具生态、执行环境、评估与奖励、控制与安全、可观测性、训练桥梁。

### 2.2 框架自适应（Harness Adaptation）—— AEGIS 引擎
- **操作镜像（Operational Mirror）**：将框架演化映射为符号空间中的强化学习MDP。状态 s_t = (H_t, T_t)（框架配置+轨迹存储），动作 a_t 是类型安全的框架编辑（代码级产物），反馈是执行轨迹+验证器得分。标准的RL病理（奖励破解、灾难性遗忘、欠探索）在符号空间中出现并放大。
- **AEGIS 四阶段流水线**：
  - **Digester（消化器）**：将原始轨迹（例如GAIA单轮约10M令牌）压缩为结构化的逐任务摘要，包括二元结果、失败类别、涉及组件等。
  - **Planner（规划器）**：接收摘要并构建适应景观（哪些任务失败、哪些编辑尝试过、哪些组件被涉及、哪些编辑类型未尝试），防止欠探索。
  - **Evolver（演化器）**：生成1个或多个候选框架 {H̃^k_t}，每个附带变更清单（change manifest）和烟雾测试。
  - **Critic（批评者）**：评估候选框架的变更清单与轨迹证据的一致性，检测奖励破解；确定性门控（deterministic gate）检查配置归一化、构建测试和跷跷板约束（seesaw constraint：不得使任何先前解决的任务退化）。
- **变体隔离（Variant Isolation）**：通过集成路由维护最多K个框架变体，将每个任务路由到其集群中历史上成功率最高的变体。编辑被限定在目标变体内，防止跨任务干扰。

### 2.3 框架-模型协同演化（Harness-Model Co-Evolution）
- 在单个迭代中同时运行框架演化和模型训练，共享**重放缓冲区（replay buffer）**。每次迭代：执行rollout → 验证 → 缓冲区插入 → 框架演化（AEGIS） → 模型GRPO更新。
- **跨框架GRPO（Cross-Harness GRPO）**：将同一任务ID的所有轨迹（无论是由哪个框架版本产生的）组成一个GRPO组，计算组内相对优势。由于框架版本可能改变动作空间，GRPO仅在模型输出令牌上计算对数概率（基于每个轨迹自身框架的上下文），不要求动作空间对齐。
- **离策略训练**：行为策略对数概率在缓冲区插入时缓存，实现“无需额外rollout”的模型训练。

## 6. 主要结论与发现

1. **整体效果**：HarnessX在15个配置中改进了14个，平均绝对增益+14.5%，最高+44.0%（ALFWorld, Qwen3.5-9B）。
2. **逆缩放模式**：基线最弱的任务智能体获益最大（Qwen3.5-9B在ALFWorld上+44.0%，Sonnet 4.6仅+11.2%）。表明演化的框架解决了弱模型自身无法纠正的行为差距。
3. **变体隔离解决异质任务退化**：Global策略在GAIA GPT-5.4上停滞（Δ=0.0），变体隔离将峰值提升至87.4%（非退化，最终=峰值）。
4. **协同演化超越仅框架演化**：在GAIA和WebShop上，协同演化额外提升+4.7%（37.4→41.7%和49.0→54.0%），打破了框架独立演化的“脚手架天花板”。
5. **操作镜像验证**：三个预测的RL病理（奖励破解、灾难性遗忘、欠探索）均在实验中显现，AEGIS通过Critic和门控部分缓解，但欠探索累积和子阈值耦合仍可能绕过防护。

## 7. 优点

### 方法性亮点
- **完整的框架-模型协同演化循环**：将执行轨迹同时用于框架更新和模型训练，打破两者优化的隔阂，实现经济高效的双线提升（无需额外rollout）。
- **操作镜像理论**：将符号空间演化映射到RL概念，系统性地识别和防御病理，为设计提供了原则性指导。
- **类型化可组合框架**：通过九维分类、处理器协议和约束元数据，使演化能够安全地插入/替换/移除组件，并实现变体隔离。
- **可审计性**：每个编辑附带变更清单、燃烧测试和确定性门控结果，支持回滚和审核，增加了安全性和透明度。

### 实验性亮点
- **多基准多模型覆盖**：包括检索、具身、网页、对话、代码编辑等多样领域，及三个不同规模的模型系列，展示了泛化性。
- **丰富消融**：对比演化策略、元智能体架构、协同演化，提供了深入的分析。
- **失败案例详细解剖**：针对每个RL病理给出具体案例和检测/缓解过程，展示了方法的实际可靠性。

## 8. 不足与局限

1. **无留出评估**：所有结果基于演化所用的同一任务集，存在**过拟合和选择偏差**。泛化到同一分布下的未见任务虽合理但未验证。
2. **仅离散动作空间**：所有实验均使用基于文本的离散动作空间，未测试连续动作空间（如机器人控制）的适用性。
3. **闭源元智能体**：AEGIS需要具有多文件代码生成和结构化轨迹分析能力的元智能体。开放权重模型（如Qwen3.5-72B、Llama-4-Maverick）作为元智能体尚未测试。
4. **联合控制假设**：协同演化要求同时对框架演化和模型训练进行控制。实践中这两者常分属不同团队或组织，共享重放缓冲区在跨团队协作中不现实。
5. **基准覆盖范围有限**：SWE-bench仅55个任务的子样本，tau^3-Bench仅3个域。结论（特别是逆缩放效应）可能不适用于不同异质性任务或更大评估集。
6. **子阈值退化防护不足**：Telecom R7案例展示了连续相同类型编辑积累的子阈值耦合能够绕过跷跷板约束，直到超过检测阈值才显现退化为−14.0%。确定性门控无法处理这种累积效应。
7. **统计量信**：pass@2的二元信号可能掩盖成功概率的漂移，且由于任务数有限（如SWE-bench 55任务，每任务翻转影响~1.8%），噪声较大。
8. **成本权衡**：演化需要前期计算开销（GAIA变体隔离107.8M令牌），在低成本快速迭代场景下可能不经济。同时演化后的框架可能增加单次推理成本（ALFWorld +60%令牌）。
