## 摘要
AI智能体的性能关键取决于运行时框架，包括提示、工具、记忆和控制流，这些中介决定了模型如何观察、推理和行动。然而，当前的框架大多仍为手工构建且静态：每个新模型或任务仍需定制化脚手架，而执行过程中产生的丰富轨迹很少被提炼为系统性改进。我们提出了HarnessX，一个用于可组合、自适应且可演化的智能体运行时框架的生成器。HarnessX通过替换代数组合类型化的框架原语，通过AEGIS（一种基于轨迹驱动的多智能体进化引擎，其在符号适应与强化学习之间建立操作镜像）进行自适应，并通过将轨迹转化为框架更新和模型训练信号来闭合框架-模型循环。在五个基准测试（ALFWorld、GAIA、WebShop、tau^3-Bench和SWE-bench Verified）中，HarnessX取得了平均+14.5%（最高+44.0%）的提升，且提升幅度在基线最低时最大。这些结果表明，智能体的进步不一定仅来自模型规模扩展：从执行反馈中组合和演化运行时接口是一个可行且互补的杠杆。完整代码将在未来版本中开源。

## Abstract
AI agent performance depends critically on the runtime harness, comprising the prompts, tools, memory, and control flow that mediate how a model observes, reasons, and acts. Yet today's harnesses remain largely hand-crafted and static: each new model or task still demands bespoke scaffolding, and the rich traces produced during execution are rarely distilled back into systematic improvement. We introduce HarnessX, a foundry for composable, adaptive, and evolvable agent harnesses. HarnessX assembles typed harness primitives via a substitution algebra, adapts them through AEGIS, a trace-driven multi-agent evolution engine grounded in an operational mirror between symbolic adaptation and reinforcement learning, and closes the harness-model loop by turning trajectories into both harness updates and model training signal. Across five benchmarks (ALFWorld, GAIA, WebShop, tau^3-Bench, and SWE-bench Verified), HarnessX yields an average gain of +14.5% (up to +44.0%), with gains largest where baselines are lowest. These results suggest that agent progress need not come from model scaling alone: composing and evolving runtime interfaces from execution feedback is an actionable and complementary lever. The complete codebase will be open-sourced in a future release.

### 1. 论文的核心问题与整体含义（研究动机和背景）

当前 AI 智能体的运行时框架（即工作台，包含提示、工具、记忆、控制流等）存在三个严重缺陷：
- **手工静态**：每个新模型或新任务都需要重新定制，无法从过往执行经验中自动改进。
- **架构纠缠**：提示模板、工具封装、重试策略、记忆等混杂在相同代码路径中，修改一个组件可能无声破坏其他组件。
- **工程与训练割裂**：执行中产生的丰富轨迹被丢弃，未用于模型训练，模型改进也不反馈到框架改进。

作者指出，智能体性能不仅取决于底层模型，也取决于框架的精心设计。现有框架停留在“复制粘贴”层面的重用，缺乏结构化、可组合、可演化的基础设施。因此，论文提出 HarnessX，将框架提升为一等公民，实现可组合、自适应且可与模型协同演化的运行时生成器。

### 2. 论文提出的方法论：核心思想、关键技术细节

**核心思想**：将框架视为一等对象（first-class object），通过类型化原语（processor）在八种生命周期钩子上组装，形成一个可序列化、可比较、可替换的配置。然后，通过 AEGIS（迹驱动的多智能体进化引擎）基于执行轨迹演化框架，并通过跨工作台 GRPO 实现框架与模型的协同演化。

**关键技术细节**：
- **框架组成（Harness Composition）**：
  - 框架 H = (M, C)，M 是模型配置，C 是框架配置。
  - 框架配置 C = (P, S)，P 是钩子到处理器列表的映射（8 个钩子：task_start, step_start, before_model, after_model, before_tool, after_tool, step_end, task_end），S 是共享槽资源（工具注册表、跟踪器、工作空间等）。
  - 处理器（Processor）是异步函数，满足 `async def process(self, event) -> AsyncIterator[Event]`，可产生五种结果：透传、变换、分裂、拦截、中断。
  - 处理器带有元数据：_singleton_group（互斥类）、_order（排序提示）、_after（软依赖）。
  - 行为空间分为九个维度：模型选择、上下文组装、记忆管理、工具生态、执行环境、评估与奖励、控制与安全、可观测性、训练桥接。

- **框架自适应（Harness Adaptation）——AEGIS**：
  - 形式化框架演化为 MDP：状态是 (H_t, T_t)（当前框架配置 + 迹存储），动作是类型化编辑 e: H → H，反馈是执行迹 + 验证器分数 r。
  - **操作镜像（Operational Mirror）**：将 RL 概念映射到符号空间（表 2），预测出三种典型 RL 病态：奖励黑客（reward hacking）、灾难性遗忘（catastrophic forgetting）、欠探索（under-exploration）。
  - AEGIS 架构：四个阶段，均由同一元智能体（meta-agent）驱动，选择性调用：
    1. **Digester**：压缩原始迹（约 10M tokens → 约 10K 结构化摘要），生成每个任务的结果、失败类别、涉及组件。
    2. **Planner**：构建适应景观（哪些任务失败、哪些编辑尝试过、哪些组件被涉及、哪些编辑类型未尝试），防止欠探索。
    3. **Evolver**：生成候选框架，每个候选附带变更清单（change manifest），包括编辑的组件、预期行为效果、预计改进/退步的任务；新处理器代码需通过烟雾测试。
    4. **Critic & Gate**：Critic 评估候选，防御奖励黑客；确定性门控（determinative gate）检查清单完整性、配置规范化、构建/烟雾测试、跷跷板约束（seesaw constraint：不能退步任何先前解决的任务）。只有通过所有检查的候选才被提交。
  - **变体隔离（Variant Isolation）**：通过集成路由（Ensemble Routing）维护至多 K 个框架变体，每个任务路由到历史上在该任务簇上成功率最高的变体。当编辑改进某些任务但退步其他任务时，不拒绝编辑，而是分叉一个新变体。这使得在异构任务集上保持非退步轨迹。

- **框架-模型协同演化（Harness-Model Co-Evolution）**：
  - 协同演化迭代：固定容量的 FIFO 重放缓冲区 B。每轮：
    1. 用当前 (M_t, H_t) 滚动执行得到迹 τ_i 和奖励 r_i。
    2. 将带分数和框架版本的迹存入缓冲区。
    3. 运行 AEGIS 框架演化得到 H_{t+1}。
    4. 运行跨工作台 GRPO 更新模型参数得到 M_{t+1}。
  - **跨工作台 GRPO**：将所有具有相同任务标识符的迹（无论哪个框架版本产生）组成一个组，计算组内相对优势。这实现了任务级别的对齐，无需动作级别对齐，因此不同框架版本（可能有不同的工具模式、提示结构）可以共存于同一组。
  - 目标函数：J_GRPO(θ) = E[ min(ρ_i(θ) * Â(τ_i), clip(ρ_i(θ),1-ε_c,1+ε_c) * Â(τ_i)) ] - β * D_KL(π_θ || π_ref)。ρ_i(θ) 是重要性采样比，π_ref 是初始固定参考模型。
  - 离线策略训练：通过 FIFO 缓冲区保持最近策略版本，利用缓存的 log 概率进行梯度更新，无需额外 rollout，模型改进几乎没有额外 rollout 成本。

### 6. 论文的主要结论与发现

- **框架演化显著提升性能**：15 个配置中 14 个提升，平均 +14.5%，最高 +44.0%（ALFWorld Qwen3.5-9B）。
- **逆缩放效应**：基线最弱的智能体收益最大（Qwen3.5-9B 在 ALFWorld 上 +44.0%，而 Sonnet 4.6 仅 +11.2%），表明演化框架能弥补弱模型的行为缺口。
- **变体隔离解决异构任务集上的停滞**：GAIA GPT-5.4 从 Global 策略的 ∆=0.0 提升到 Ensemblle 的 +13.6%，且最终 =峰值（无退化）。
- **AEGIS 多阶段架构主要贡献效率而非精度**：与单智能体 CC SDK 相比，精度差距在噪音范围内（87.4% vs 86.4%），但 token 消耗减少约 12%。
- **协同演化超越框架仅演化**：在 GAIA 和 WebShop 上额外 +4.7%，打破了框架仅演化的脚手架天花板。
- **三种 RL 病态在符号空间确实出现**：奖励黑客被检测并缓解（两轮内），灾难性遗忘通过变体隔离 предотвращён（Global 策略下降 24.3pp），欠探索通过 Planner 的景观构建缓解。

### 7. 优点

- **理论框架清晰**：将框架演化映射为 MDP，预测病态并设计防御，具有指导意义。
- **模块化设计**：处理器抽象 + 类型化钩子 + 替代代数，使得框架可组合、可替换、可序列化，为自动化演化奠定基础。
- **完整的闭环**：框架演化 + 模型训练共享同一重放缓冲区，实现高效协同优化（无额外 rollout 成本）。
- **强大的可观测性**：全迹记录 + 结构化压缩，使得 Digester 能诊断失败根因，Critic 能检测奖励黑客。
- **变体隔离**：通过集成路由实现非退化演化，解决了长期困扰自改进系统的灾难性遗忘问题。
- **广泛的基准覆盖**：涵盖了检索、具身、网页、对话、编码五个典型领域，模型跨度从 9B 到前沿闭源，验证了泛化性。
- **失败分析深入**：通过案例研究展示了每种病态的具体表现和检测机制，增强了方法的可信度。

### 8. 不足与局限

- **缺乏 held-out 评估**：所有提升均基于进化集自身，可能存在过拟合；未测试泛化到未见任务的能力。
- **仅离散动作空间**：实验限于基于文本的离散动作智能体，未验证连续动作空间（如机器人控制）的适用性。
- **闭源元智能体**：AEGIS 依赖强大的闭源模型（Claude Opus 4.6）作为元智能体，未测试开源模型效果（如 Qwen3.5-72B、Llama-4-Maverick）。
- **联合控制假设**：协同演化需要同时控制框架演化和模型训练，实际中通常分属不同团队，协调困难。
- **基准覆盖有限**：SWE-bench 仅用 55 任务子集，τ³-Bench 仅三个领域，结论可能不适用于更大规模或更异质的任务集。
- **成本分析不完整**：虽然报告了 token 消耗，但未给出总 GPU 小时数或总成本；演化成本能否在部署中摊销取决于应用场景。
- **门控机制局限**：跷跷板约束基于 pass@2 的二元信号，无法检测小于此阈值的渐进式退化（如 τ³-Bench Telecom 案例），导致积累性耦合未被及时捕捉。
- **伦理考虑**：自进化系统需要监督，论文提出了审计性、确定性门控和人类介入，但未讨论恶意使用或安全对齐风险。
