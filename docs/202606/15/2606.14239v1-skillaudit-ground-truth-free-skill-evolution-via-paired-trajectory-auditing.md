## 摘要
智能体技能是结构化的程序包，用于指导冻结的LLM智能体执行专门的工作流程。技能在部署后很少能保持足够：边缘情况、API更改和部署约束只有在使用中才会显现，因此技能演化成为实际需求。现有方法依赖于特权反馈，如保留验证分数、隐藏测试结果或环境奖励——当从业者仅有任务描述和工作区数据时，这些信号通常不可用。我们提出了SkillAudit，一个无需真实标签反馈即可演化智能体技能的框架。关键思想是配对轨迹审计：在每次迭代中，同一任务分别在有和没有候选技能的情况下执行，从而在无外部标签的情况下分离出技能如何改变智能体行为。为了将行为差异转化为编辑指导，SkillAudit使用了流程对齐对比评估（PACE），这是一组评估器，将轨迹发散映射到与技能文档中特定段落相关的诊断信号。一个结构验证器（根据任务规范编译一次后固定）检查任务约束并回滚有害更新。SkillAudit通过两条流水线路由编辑：Refine从广泛有用的技能中移除噪声或无关指导，而Repair替换与任务冲突的段落。在跨越8个专业领域的89个容器化任务中，SkillAudit实现了73.9%的平均任务奖励，优于没有技能的智能体（40.9%）和静态专家技能（56.7%）。这些增益是在演化过程中未访问隐藏测试、参考解决方案或外部评分函数的情况下获得的。

## Abstract
Agent skills are structured procedural packages that guide frozen LLM agents in specialized workflows. Skills rarely remain sufficient after deployment: edge cases, API changes, and deployment constraints become visible only through use, making skill evolution a practical necessity. Existing methods depend on privileged feedback such as held-out validation scores, hidden test outcomes, or environment rewards -- signals often unavailable when a practitioner has only a task description and workspace data. We introduce SkillAudit, a framework for evolving agent skills without ground-truth feedback. The key idea is paired trajectory auditing: at each iteration, the same task is executed with and without the candidate skill, isolating how the skill changes agent behavior without external labels. To turn behavioral differences into edit guidance, SkillAudit uses Process-Aligned Contrastive Evaluation (PACE), a cluster of evaluators that maps trajectory divergences to diagnostic signals linked to specific passages in the skill document. A structural verifier, compiled once from the task specification and then fixed, checks task constraints and rolls back harmful updates. SkillAudit routes edits through two pipelines: Refine removes noisy or irrelevant guidance from broadly useful skills, while Repair replaces passages that conflict with the task. Across 89 containerized tasks spanning 8 professional domains, SkillAudit achieves 73.9% average task reward, outperforming an agent without skills (40.9%) and the static expert skill (56.7%). These gains are obtained without accessing hidden tests, reference solutions, or external scoring functions during evolution.

## 2. 提出的方法论

### 核心思想：配对轨迹审计（Paired Trajectory Auditing）
- 在每次迭代中，同一任务分别 **有技能**（τw）和 **无技能**（τwo）执行一次，形成轨迹对。
- 通过对比两条轨迹的行为差异，隔离出技能对智能体行为的影响，无需外部标签即可产生编辑指导信号。

### 关键技术细节

#### ① 评估基础设施
- **PACE（Process-Aligned Contrastive Evaluation）**：一组 12 个评估器，分为四个维度：
  - Process Adherence（过程遵循）
  - Artifact Evidence（工件证据）
  - Consistency（一致性）
  - Effectiveness Delta（效果差异）
- 每个评估器输出：通过/失败/警告、技能文档中具体段落的锚定诊断信号（verbatim segment quote）、受保护提示。
- **Anchor Verifier（结构验证器）**：从任务规范编译一次后锁定，检查可客观验证的约束（文件存在、格式合规、可重算的值等），作为硬约束，确保演化不违反任务要求。

#### ② 决策机制（三个判定）
- **skill helped**：接受更新
- **skill hurt**：回滚到之前版本（具有最高优先级，任何评估器报告 hurt 即 veto）
- **skill inert**：延迟（defer）

#### ③ 双策略演化管道
- **Refine**（减法优先）：适用于技能基本正确但包含噪声、冗余或轻微偏差。通过删除无关内容来改进。
- **Repair**（替换/诊断驱动）：适用于技能核心工作流与任务冲突（如过时 API、错误输出格式）。通过定位有害段落并用 τwo 中的已验证替代片段交换或删除来修复。

#### ④ 演化循环（Algorithm 1）
1. 初始化：任务解释器分析 T 和 S0，生成结构化规范；编译 Anchor Verifier；预兼容性评估路由到 Refine 或 Repair。
2. 每迭代（最多 5 次）：
   - 配对执行获得 τw、τwo
   - PACE + Anchor Verifier 聚合给出 verdict
   - 若 helped → Skill Iterator 执行编辑；若 hurt → 回滚；若 inert → 继续。
   - 检查收敛：最近两次无 hurt、Anchor 通过、无手术目标 → 终止。

## 3. 实验设计

- **Benchmark**：SkillsBench（最新版本 + v1.1 扩展），过滤后得到 **89 个可执行任务**，覆盖 8 个专业领域（软件工程、办公室文职、自然科学、工业与物理系统、金融与经济、数学与运筹学、网络安全、媒体与内容生产）。
- **对比基线**：
  - No skill：智能体不带任何技能执行任务
  - With skill：SkillsBench 自带的专家编写的静态技能（最佳静态基线）
  - **无其他技能演化方法比较**（因为那些方法依赖外部信号，无法在同一设定下公平对比）

## 6. 主要结论与发现

- **主结果**：SkillAudit 在 89 个任务上平均奖励 **73.9%**，超越无技能（40.9%）和静态技能（56.7%），提升分别为 +33.0 pp 和 +17.2 pp。
- **技能伤害恢复**：3 个有技能比无技能更差的任务，通过 skill-hurt veto 全部恢复至 1.0。
- **可观测性边界**：技能演化成功与否由技能知识的“可观测性”决定，而非领域。基于可执行/可观察知识（API 调用、数学方法）的技能演化效果好（~80%），基于领域过程（不可观测的结构化知识）的技能演化效果差（~69%）。不可观测知识的任务是失败集的主体。
- **编辑模式**：演化产生一种小而一致的编辑词汇表：修剪无关技能、剥离教程保留可执行核心、去硬编码、约束内联、添加 I/O 契约、修复小错误。并且**系统自动创建索引/路由表**（80/89 个演化技能包含），作者认为导航性是可使用技能的一阶属性。
- **长度变化**：技能向信息密集的中间地带收缩（小型技能增长填充契约、大型技能被修剪），最终收敛到紧凑区间。

## 7. 优点

1. **创新性强**：首次提出并验证了在完全无外部真实标签反馈条件下进行技能演化的可行方案。
2. **方法设计精良**：
   - 配对轨迹审计巧妙地将技能影响从任务难度中分离。
   - PACE 将粗粒度轨迹差异细化为段落级别的诊断信号，实现精准编辑。
   - Anchor Verifier 提供静态、确定性约束，作为硬边界防止评估器漂移和有害更新。
   - Refine/Repair 双管道区分噪声修正和冲突修复，降低误修改风险。
3. **实验设置严谨**：严格分离演化与评估（容器隔离、无法访问测试内容），保证无反馈约束真实成立。
4. **分析深入**：不仅报告整体指标，还深入剖析演化成功/失败的根本原因（可观测性边界），并提供详细案例和技能结构分析，结论有洞察力。
5. **实用价值高**：方法只需任务描述和工作区数据，适用于现实中的甲方环境（没有测试集、奖励函数、oracle 等基础设施）。

## 8. 不足与局限

1. **缺乏系统消融实验**：无法确定各组件（配对执行、PACE、Anchor Verifier、双管道）的具体贡献，以及是否所有组件都负载必需。
2. **预评估路由的可靠性未量化**：Refine/Repair 的初始分配可能错误，且未讨论误路由后果。
3. **仅测试单模型**：演化与评估均使用 Claude Opus 4.8，未验证演化后的技能是否能跨模型迁移（是否捕获了真正的过程知识而非模型特异性），也未测试更弱模型的效果。
4. **可观测性边界带来的本质限制**：对于存在于领域过程且无结构可观测痕迹的知识，SkillAudit 无法改进（77% 的失败任务因此），需要人工或更强 oracle 提供信号。
5. **未比较其他无反馈启发式方法**：例如直接使用 LLM 自我反思或基于单轨迹的差异（无需配对）是否同样有效？缺乏这类对比降低了方法的相对说服力。
6. **收敛条件可能过早**：5 次迭代上限可能不足以解决复杂任务，且收敛条件依赖 Anchor 通过和最近无 hurt，但可能忽略潜在但未暴露的问题。
7. **评估仅使用一个指标（平均任务奖励）**：未报告方差、置信区间或统计显著性检验，也未考虑不同困难任务的权重。
8. **潜在过拟合风险**：虽然未访问测试，但 Anchor Verifier 和 PACE 均基于任务描述和工作区，若任务描述有歧义或 PACE 评估有偏差，可能收敛到次优解。
