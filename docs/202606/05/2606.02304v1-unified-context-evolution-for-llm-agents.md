## 摘要
基于LLM的智能体可以通过将推理与环境反馈相结合来解决多步交互任务，然而每个回合都从相同的固定上下文开始，并且在此过程中发现的任何有用策略在任务结束后都会丢失。现有方法要么将学习限制在当前任务，要么将所有经验汇集到一个单一的无类型存储中，而不区分知识类型、通过使用情况跟踪质量或平衡库中仍然缺失的内容。我们引入了统一上下文演化（UCE），这是一种无梯度框架，将智能体经验外部化为一个由可演化类型上下文单元（ECU）组成的演化库。UCE将经验分解为四种互补类型（记忆、策略、工作流和技能），每种类型都从轨迹中在特定类型条件下生成，在决策时检索，通过重复使用结果进行评分，并在不再有价值时进行剪枝。一个调度模块将每个周期的生成预算分配给库中最薄弱的类型。在两个交互基准测试中，UCE将ALFWorld的成功率从75.4%提高到96.3%，将WebShop的任务得分从45.1%提高到61.3%，并且累积的库可以迁移到其他智能体骨干网络而无需重新训练。

## Abstract
LLM-based agents can solve multi-step interactive tasks by combining reasoning with environment feedback, yet each episode starts from the same fixed context and any useful strategy discovered along the way is lost once the task ends. Existing approaches either limit learning to the current task or pool all experience into a single untyped store, without distinguishing knowledge types, tracking quality through use, or balancing what the library still lacks. We introduce Unified Context Evolution (UCE), a gradient-free framework that externalizes agent experience into an evolving library of typed Evolvable Context Units (ECUs). UCE decomposes experience into four complementary types (Memory, Strategy, Workflow, and Skill), each generated from trajectories under type-specific conditions, retrieved at decision time, scored through repeated usage outcomes, and pruned when no longer valuable. A scheduling module allocates each cycle's generation budget toward the types where the library is weakest. Across two interactive benchmarks, UCE raises ALFWorld success from 75.4% to 96.3% and WebShop task score from 45.1% to 61.3%, and the accumulated library transfers to alternative actor backbones without retraining.

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：基于LLM的智能体在每次执行交互任务时，均从相同的固定上下文（如系统指令、少样本示例等）开始；任务期间发现的有用策略（如环境机制、决策规则）随任务结束而丢失，无法跨任务积累。
- **现有方法不足**：
  - 强化学习需要梯度访问和高昂成本。
  - 任务内适应方法（如Reflexion）的改进局限于当前任务。
  - 跨任务知识库方法要么将所有经验混入无类型池中，要么只存储单一知识形式，且缺乏质量跟踪和资源分配的动态平衡。
- **研究意义**：提出一种无梯度、可跨任务演化的上下文学习框架，使智能体在不更新模型权重的情况下持续积累和利用经验，提升多步交互任务的性能。

## 2. 方法论
### 核心思想
- **统一上下文演化（UCE）**：将智能体经验外部化为一个可演化的**可演化上下文单元（ECU）** 库。每个ECU是有类型、有质量分数的知识条目，通过生成、使用评分、剪枝不断演化，并在决策时注入到智能体提示中。
### 关键技术细节
- **四种ECU类型**（表1）：
  - **Memory（记忆）**：环境机制事实性陈述，从单条轨迹生成。
  - **Strategy（策略）**：条件决策规则（IF-THEN），从相同任务类型的多条轨迹生成。
  - **Workflow（工作流）**：任务类型的标准执行序列，从成功轨迹生成。
  - **Skill（技能）**：可跨任务类型复用的多步子操作方法，从多种任务类型轨迹生成。
- **ECU表示**：五元组 `(类型, 任务类型, 检索条件, 内容, 适应度分数)`。
- **检索公式**（公式2）：语义相似度 + 任务类型匹配提升（β） + 质量偏置（λ），并按类型独立排序，每类型取Top-K注入提示。
- **适应度分数**（公式3）：Laplace平滑 `fe = (se + 1)/(ue + 2)`，其中 `se` 为累积成功/奖励，`ue` 为使用次数。新ECU初始分数0.5。
- **演化周期**（五个阶段，图2）：
  1. **评估**：在保留集上运行智能体，记录成功率（不更新分数）。
  2. **收集**：在互斥收集集上运行智能体，更新适应度分数。
  3. **调度（KYS）**：基于库状态、收集成功率、历史收益，分配每类型生成预算。
  4. **生成**：使用类型特定提示从收集轨迹中提取候选ECU，经重排测试和去重后加入库。
  5. **清理**：移除低适应度或冗余ECU。
- **知识收益调度（KYS）**（三层）：
  - 第一层：可行性过滤（类型是否还有覆盖空白）。
  - 第二层：需求评估（覆盖缺口 + 质量缺口）。
  - 第三层：收益追踪（指数移动平均历史回报）。
  - 融合得分分配预算，并确保每种可行类型获得最低份额。

## 3. 实验设计
- **数据集/场景**：
  - **ALFWorld**：134个家务任务，6种类型（Pick, Look, Clean, Heat, Cool, Pick2）。文本环境，离散动作。
  - **WebShop**：100个在线购物任务，5种产品类别。连续奖励评分（0~1）。
- **基准对比方法**：
  - ReAct（基线）
  - ExpeL（跨任务无类型经验池）
  - Reflexion（任务内多轮反思）
  - 三种不同推理骨干：NoThinking、Plan-and-Act、ReflAct（各自有/无ECU库）
- **评估协议**：ALFWorld运行5个周期，WebShop运行11个周期。周期0为ReAct基线，每个任务在每个周期执行一次（无多次尝试）。

## 6. 主要结论与发现
- **性能提升显著**：
  - ALFWorld成功率从75.4%提升至96.3%（+20.9个百分点）。
  - WebShop任务分数从45.1%提升至61.3%，购买成功率从30.0%提升至42.0%。
- **库可迁移**：积累的ECU库可无缝应用于NoThinking、Plan-and-Act、ReflAct等不同推理骨干，均带来稳定提升（ALFWorld峰值达97.8%，WebShop达66.8%）。
- **类型互补**：
  - ALFWorld上，单用Workflow即接近全库性能（97.0% vs 96.3%），说明该基准主要依赖过程性知识。
  - WebShop上，单类型均不如全库（最佳单类型36.0% vs 全库42.0%），表明购物任务需要多种知识类型协作。
- **场景举例**：WebShop枕头案例中，全库通过Memory、Workflow、Strategy三类ECU联合解决子标签导航陷阱，而单一类型均失败。

## 7. 优点
- **无梯度框架**：不更新模型权重，适用于闭源LLM，无需昂贵训练。
- **类型化知识表示**：将经验分解为四种互补粒度（事实、决策、流程、方法），独立生成、检索、剪枝，避免一个类型压制其他。
- **基于使用质量的动态评估**：适应度分数基于实际使用结果而非一次性LLM评分，更准确反映ECU价值。
- **智能调度（KYS）**：利用库内置结构信息（覆盖、质量、历史收益）自动分配生成预算至薄弱类型，提升演化效率。
- **库可迁移性**：ECU独立于具体提示格式，可搭配多种推理骨干，实用性强。

## 8. 不足与局限
- **实验覆盖有限**：仅在两个文本环境（离散动作、短规划长度）上评估，未涉及连续动作、多模态观测（如AndroidWorld、VisualWebArena）或更长规划周期。
- **模型对依赖性**：当前结果基于单一模型对（gpt-4.1-mini + gpt-5.2），无法分离框架设计与生成器能力各自贡献。
- **任务池较小**：ALFWorld 134任务、WebShop 100任务，调度信号估计可靠性、库在更大规模或更长演化下的行为未知。
- **类型设计手工化**：四种ECU类型为人工定义，未实现自动类型发现，难以适应开放域新任务。
- **KYS信号估计偏差**：从有限任务集估计覆盖和收益，噪声可能影响预算分配有效性。
- **因果分离不足**：未与同类型更细粒度消融（如不同KYS变体）对比，框架各部分贡献量化不够精细。
