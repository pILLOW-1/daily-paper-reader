## 摘要
大型语言模型智能体越来越多地面临长期任务，如实际应用中的网络搜索和深度研究，其中累积的上下文可能导致长上下文退化和推理失败。先前的工作通过智能体端上下文控制或固定策略（如摘要）来缓解这一问题，这需要训练智能体自身进行适应——这对于闭源智能体来说不切实际，并且忽略了不同智能体可能需要不同的策略。我们提出自适应上下文管理（AdaCoM），它通过灵活的修改操作和端到端强化学习训练一个外部语言模型来管理冻结智能体的上下文。在网络搜索和深度研究基准测试中，针对多种智能体，AdaCoM通过保留任务约束和进展同时剪枝过时内容，显著提升了性能。学习到的策略揭示了保真度-可靠性权衡：具有较高原始ReAct性能的智能体从更高保真度的上下文保留中受益，而性能较低的智能体需要更积极的压缩以保持在可靠的推理范围内。迁移实验表明，AdaCoM在能力相似（通过原始ReAct性能衡量）的智能体间泛化效果最佳，这为智能体系统提供了可重用上下文管理器的实用路径。

## Abstract
LLM agents increasingly face long-horizon tasks such as web search and deep research in real-world applications, where accumulated context can cause long-context degradation and reasoning failures. Prior work mitigates this through context management with agent-side context control or fixed strategies such as summarization, which require training the agent itself for adaptation - making it impractical for closed-source agents and ignoring that different agents may require different strategies. We introduce Adaptive Context Management (AdaCoM), which trains an external LLM to manage the context of a frozen agent through flexible modification actions and end-to-end reinforcement learning. Across diverse agents on web search and deep research benchmarks, AdaCoM substantially improves performance by preserving task constraints and progress while pruning stale content. The learned strategies reveal a Fidelity-Reliability Trade-off: agents with higher vanilla ReAct performance benefit from higher-fidelity context preservation, whereas lower-performing agents require more aggressive compression to stay within a reliable reasoning regime. Transfer experiments show that AdaCoM generalizes most effectively across agents with similar capability (measured by vanilla ReAct performance), suggesting a practical path toward reusable context managers for agent systems.

- **现有方法局限**：
  - 现有上下文管理方法（如摘要、裁剪工具）通常将管理责任放在智能体自身，要求智能体学习何时及如何管理上下文，这需要训练智能体本身。

- **核心动机**：能否在不训练智能体本身的前提下，为每个智能体发现其偏好的上下文管理策略？这引出了**自适应上下文管理（AdaCoM）**。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想

- **架构解耦**：上下文管理由外部“管理者”（Manager）负责，通常是较小的LLM（如Qwen3-4B-Instruct），而目标智能体（Agent）保持完全冻结、不可训练。
- **操作级灵活性**：管理者不依赖预定义操作（如摘要），而是可以自由修改上下文中的任何消息：重写、删除、合并或保持原样。修改动作表示为结构化JSON列表，包含目标消息ID、角色、理由和新内容。

### 2.2 关键技术细节

- **工作流程**：
  1. 在第t轮，冻结智能体基于管理者维护的托管上下文 ˜c_{t-1} 生成动作 a_t，环境返回观察 o_t。
  2. 将 (a_t, o_t) 追加得到预管理上下文 c_t = Append(˜c_{t-1}, a_t, o_t)。
  3. 管理者根据当前上下文生成结构化修改动作 m_t ∼ π_θ(·|p_t)，其中 p_t = P(c_t) 是包含管理指令和输出模式的提示。
  4. 应用 m_t 得到新的托管上下文 ˜c_t，供下一轮智能体使用。

- **动作空间**：每个修改操作包含：ids（目标消息ID列表）、role（system/user/assistant）、justification（修改理由，不展示给智能体）、new_content（新内容，空字符串表示删除）。支持的操作包括：更新任务约束笔记、删除过时工具结果、合并相关消息、保持上下文不变等。

- **训练方法**：
  - **两阶段训练**：先使用监督微调（SFT）让管理者学习输出格式；再用强化学习（GRPO）优化。

      - 令牌惩罚：托管上下文超出长度限制时惩罚。
      - 冗余动作惩罚：智能体连续两次调用相同工具且参数相同时惩罚。
      - 格式惩罚：JSON解析失败、ID不存在等。

## 6. 主要结论与发现

1. **AdaCoM显著提升性能**：在所有智能体上，AdaCoM相较ReAct获得平均39.0%的mean@3相对提升，其中对Kimi提升达95.0%。在MCP-Bench-Wiki上，Kimi提升9.0%，DeepSeek提升22.3%。
2. **训练是必要的**：无训练的AdaCoM表现不稳定且平均下降，说明必须通过RL学习有效策略。
3. **固定摘要不适用于所有智能体**：SumCoM对部分智能体有效，但对GLM产生负面效果，表明灵活修改操作比固定摘要更优。
4. **保真度-可靠性权衡**：管理者学到的策略与原智能体ReAct能力相关。更强智能体（如GLM、Qwen）的管理者保留更多原始上下文（高保真度），而更弱智能体（如DeepSeek、Kimi）的管理者更积极压缩（高可靠性）。这揭示了每个智能体存在一个有效上下文长度，超过后额外原始上下文反而有害。
5. **迁移性依赖于能力相似性**：管理者在原始ReAct性能接近的智能体间迁移效果最好。能力相近的源-目标对通常获得较大增益，但管理者的改写风格与目标智能体推理风格的兼容性也影响迁移质量。
6. **下行影响**：AdaCoM帮助智能体减少约束遗忘、过早放弃和重复探索。
