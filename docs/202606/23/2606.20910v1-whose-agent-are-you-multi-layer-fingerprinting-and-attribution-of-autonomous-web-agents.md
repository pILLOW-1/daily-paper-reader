## 摘要
随着AI网络代理的激增，将大型语言模型与自主浏览器级控制相结合，网络代理的无差别内容抓取已成为隐私和安全挑战。现有的防御措施，如robots.txt和主动机器人拦截，已显不足，因为它们被广泛违反且易于规避。在本工作中，我们证明基于网络层特征（如TLS、HTTP）和浏览器交互行为的多层指纹可有效区分AI网络代理与人类及传统爬虫。我们将此机制实现为一个可编程日志框架，可部署于实时检测的域名上。通过分析六个主流代理框架（AutoGen、Browser Use、Claude、Gemini、Operator和Skyvern），我们揭示了这些系统在组装HTTP请求、建立TLS/HTTP连接以及执行自主浏览器动作方面的潜在结构差异。将这些多层特征输入决策树分类器，我们的框架实现了高保真识别（97%准确率），成功隔离了不同代理架构，并将代理流量与人类浏览基线和传统爬虫区分开。我们的发现表明，跨层代理追踪为内容保护和网络安全策略执行提供了一种鲁棒且抗规避的策略。

## Abstract
As AI web agents proliferate, combining large language models with autonomous, browser-level control, indiscriminate content scraping by web agents has emerged as a privacy and security challenge. Existing defenses, such as robots.txt and active bot-blocking, are insufficient, as they are widely violated and easily circumvented. In this work, we demonstrate that AI web agents can be effectively distinguished from humans and traditional crawlers using a multi-layer fingerprint based on both network layer characteristics (e.g., TLS, HTTP) and browser interaction behavior. We implement this mechanism as a programmatic logging framework that can be deployed on a live, instrumented domain.   By analyzing six prominent agent frameworks (AutoGen, Browser Use, Claude, Gemini, Operator, and Skyvern), we uncover latent structural differences in how these systems assemble HTTP requests, establish TLS/HTTP connections, and execute autonomous browser actions. Feeding these multi-layer features into a decision tree classifier, our framework achieves high-fidelity identification (97% accuracy), successfully isolating distinct agent architectures and differentiating agent traffic from both human browsing baselines and legacy crawlers. Our findings demonstrate that cross-layer agent tracking provides a robust, evasion-resistant strategy for content protection and web security policy enforcement.

## 6. 主要结论与发现

- **跨层组合最优**：四层特征组合的Extra Trees分类器达到**97%准确率**（F1=0.971），高于单独使用任一层（时序100%但仅适用于完整轨迹；行为F1=0.876；HTTP=0.820；TLS=0.747）。
- **各层特点**：
  - **时序**：完整轨迹下100%区分，但早期请求（<30个）性能极低（近乎零F1），不适合实时检测。
  - **TLS/HTTP**：在收到约3个请求后即可达到>60%的宏F1，适合早期部署；但Claude和Gemini在该层几乎无法区分（Gemini TLS F1=0.000）。
  - **行为**：中后期性能提升快，能区分网络层相似的代理（如Claude vs. Gemini），但Operator因高变异性行为F1最低（0.621）。
- **各代理独有指纹**：
  - Skyvern：唯一个具有17个TLS扩展、JA4 c哈希唯一、流5权重110，以及极长鼠标轨迹（行为）——易识别。
  - Browser Use：100%的Sec-Fetch逻辑违规，且使用非标准头顺序。
  - AutoGen、Claude、Gemini：高度头端/自动化特征（大量HeadlessChrome、缺失Accept-Language、Sec-Fetch-Site始终为none）。
  - Operator：唯一显示Firefox JA4（39%流量），并引入自定义头`signature`，但行为高变异性最难识别。
- **实时识别可行性**：结合所有特征，接收3个请求后即可达到>60%宏F1，可用于内容选择性投放前的代理检测。

## 7. 优点

1. **多层互补设计**：综合利用协议层和行为层，克服单一特征的弱点（如Claude和Gemini在TLS/HTTP上难以区分但行为不同）。
2. **真实部署场景**：搭建了完整的前后端测试平台，包含5个精心设计的UX陷阱，可暴露代理在不同感知模式（视觉/结构/无障碍树）下的系统性差异。
3. **抗规避潜力**：即使代理模仿人类HTTP头（如Skyvern），其行为特征（鼠标轨迹、事件比例）仍可暴露身份。
4. **实用性**：分类器可在接收少量请求后实时决策，支持在线内容保护。
5. **实验严谨**：重复30次，使用交叉验证，对比不同特征组合，并包含传统爬虫和人类基线。

## 8. 不足与局限

1. **特征时效性**：AI代理架构和骨干模型快速迭代（如Chrome版本、HTTP/2优先级策略变化），当前指纹可能很快过时，需持续更新。
2. **无法识别完美模仿者**：若代理完全复制人类网络和行为模式（如使用真实浏览器、模拟人类鼠标模式），框架将无法区分。
3. **场景限制**：测试任务固定、时间短（7个页面），未覆盖复杂多步任务或跨站点导航；行为特征准确性可能随网站设计改变。
4. **时序特征局限性**：时序特征依赖完整轨迹才能达到100%准确率，但实际中任务类型、网络延迟、提示措辞都会引起偏移，模型泛化性存疑。

6. **仅在特定骨干模型上测试**：开源代理使用了GPT-5-mini，未评估其他LLM（如Claude、Gemini的开源版本）作为骨干时的泛化能力。
