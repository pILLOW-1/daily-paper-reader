## 摘要
网络上丰富的程序性知识在帮助智能体解决长周期任务方面具有巨大潜力。然而，这类知识通常是多模态、异质、嘈杂的，并且隐含地假设人类执行者，这使得它们难以直接用作智能体所需的技能。为了弥合面向人类的指南与智能体可执行技能之间的鸿沟，我们将这一问题形式化为“指南到技能学习”：将野外指南转化为可执行技能，并从智能体可观察到的轨迹中持续改进这些技能。为了评估现有智能体在此任务上的能力，我们引入了MMG2Skill-Bench——首个针对该问题的基准测试。我们进一步提出了MMG2Skill，这是一个闭环框架，它将指南编译为可编辑的技能，在执行过程中基于这些技能对固定的视觉语言模型（VLM）智能体进行条件化，并从轨迹级别的根本原因反馈中修正技能，而不使用基准测试分数。在GUI控制、开放结局游戏和策略卡牌游戏这六个VLM骨干网络上，MMG2Skill在每个模型-领域设置中都始终优于原始的基线智能体，在不同骨干网络上实现了宏观平均提升12.8到25.3个百分点。消融研究表明，直接用原始指南提示智能体可能会降低性能，而结构化的技能构建和轨迹驱动的修正对于观察到的改进都是必要的。在可推断成功性的任务中，基于分析器的提前停止进一步防止了后期性能退化，并在成功信号得到适当校准的情况下节省了25%-53%的尝试次数。

## Abstract
Abundant procedural knowledge on the Web holds great potential for helping agents solve long-horizon tasks. However, such knowledge is often multimodal, heterogeneous, noisy, and implicitly assumes human executors, making it difficult to use directly as the skills required by agents. To bridge the gap between human-oriented guides and agent-executable skills, we formalize this problem as guide-to-skill learning: converting in-the-wild guides into executable skills and continuously improving them from trajectories observable to the agent. To evaluate the capability of existing agents on this task, we introduce MMG2Skill-Bench, the first benchmark designed for this problem. We further propose MMG2Skill, a closed-loop framework that compiles guides into editable skills, conditions a fixed vision-language model (VLM) agent on these skills during execution, and revises the skills from trajectory-level root-cause feedback without using benchmark scores. Across GUI control, open-ended gameplay, and strategic card play with six VLM backbones, MMG2Skill consistently outperforms vanilla baseline agents in every model-domain setting, achieving macro-average gains of +12.8 to +25.3 percentage points across backbones. Ablation studies show that directly prompting agents with raw guides can degrade performance, while both structured skill construction and trajectory-driven revision are necessary for the observed improvements. On success-inferable tasks, analyzer-based early stopping further prevents late-stage performance regressions and saves 25%-53% of attempts when the success signal is properly calibrated.

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：MMG2Skill 是一个闭环框架（Closed-Loop Framework），它不更新VLM参数（固定策略），而是通过外部可编辑技能缓存注入程序性知识，并依据轨迹级错误分析自动修订技能。整个循环四阶段：
  1. **多模态技能构造（Skill Construction）**  
     将原始指南（HTML+图像）转化为结构化 SKILL.md 文件，每个技能包含：可复用过程、适用条件、预期状态线索、恢复知识。公式为：
     ```
     S1 = CONSTRUCT_SKILLS(G, I) = {z_i}
     z_i = (u_i, c_i, v_i, q_i)
     ```
     由VLM一次性完成，无需人工标注。

  2. **技能条件执行（Skill-Conditioned Execution）**  
     在每次尝试开始时，将当前技能集 $S_k$ 注入到VLM Agent的上下文，Agent每一步根据任务、历史和技能采样动作：
     ```
     a_t ∼ π_θ(a_t ∣ h_t, I, S_k)
     ```
     技能不改变域动作接口，可跨领域复用。

  3. **分析器（Analyzer）**  
     只读取任务指令和Agent可见轨迹（不访问环境隐藏状态或分数），输出诊断 $\rho_k = (e_k, r_k)$：$e_k$ 为轨迹证据（什么工作、什么失败、根因），$r_k$为成功判断（likely_success/uncertain/likely_failure）。支持分块阅读长轨迹以控制上下文长度。

  4. **精炼器（Refiner）**  
     结合原始指南、当前技能和全历史诊断（最多保留先前所有分析结果），对技能进行本地化编辑（添加缺失检查、锐化状态信号、强化成功行为、移除误导恢复建议）：
     ```
     S_{k+1} = REFINE(G, I, S_k, ρ_{1:k})
     ```
     仅编辑技能文件，不使用benchmark分数。

- **早停策略**：当分析器输出 `likely_success` 时，停止尝试并返回当前技能和轨迹；若预算内未触发则取最后一次尝试。对比全运行（full-run）策略。

### 3. 实验设计：数据集 / 场景、Benchmark、对比方法

- **指南来源**：GUI使用产品文档/How-to文章；Game使用Wiki页面和攻略；Strategy使用规则描述和初级策略材料。每种任务提供对应的多模态材料（HTML+图像/截图）。
- **对比方法**：
  - **Vanilla**：无任何外部技能。
  - **Raw Guide**：直接将原始指南（多模态）注入Agent，不进行技能构造和修订。
  - **MMG2Skill（主方法）**：全闭环，使用早停策略（首次likely_success）。

- **评测**：每个任务分数[0,1]，使用域原生评估器（OSWorld评分、Minecraft任务判断、RLCard收益）。
- **VLM骨干**：6个模型：Claude-Opus-4.6, GPT-5.5, Claude-Sonnet-4.6, Kimi-K2.6, Gemini-3.1-Pro-Preview, Qwen3.6-Plus。尝试预算N=5，每个模型完全独立运行。

### 6. 论文的主要结论与发现

1. **公共指南可提升VLM智能体**，但直接提示原始指南可能有害（在Game和Strategy上甚至下降1.67pp），因为指南中存在隐式假设、导航文本、运行时不可用步骤等接地不匹配。
2. **MMG2Skill在所有18个模型-领域单元格中一致超越Vanilla**，宏观平均提升+12.8到+25.3个百分点。收益在弱模型上尤其显著（Qwen提升+25pp）。
3. **结构化技能构建提供安全程序先验**：仅构造无修订已不低于Vanilla（在Strategy+1.25pp），而修订贡献大部分增益（Game上+22.22pp）。
4. **修订增益非单调**：全运行（取最后尝试）在Game和Strategy上可能出现晚期衰退，早停策略（分析器判断likely_success）更安全。
5. **早停节省尝试次数**：在成功可推断任务上，节省25.44%–52.92%的尝试，对应API调用节省23.60%–41.77%；精度≥74%，重写对GUI和Game召回率≥95%。
6. **剩余失败领域特异**：GUI失败源于接地、诊断与技能信息耦合；Game失败来自过程脆弱性（预算用尽、接地错误）；Strategy失败来自决策规则转换难题。

### 7. 优点

- **闭环中无分数反馈**：分析器和精炼器仅使用Agent可见轨迹信息，不依赖benchmark分数，更接近真实部署场景。
- **领域多样性**：覆盖桌面GUI、开放世界游戏、策略卡牌三个截然不同的交互模式，验证了方法通用性。

- **实用早停机制**：提出并校准了分析器驱动的早停信号，在保证性能的同时降低部署成本。
- **失败归因分析**：对残留失败按流水线组件分层编码，揭示不同领域瓶颈，为后续改进指明方向。

### 8. 不足与局限

- **不处理上游指南发现/选择**：假设已提供任务相关指南，未涉及多源检索、过时过滤、质量评估等问题；低质量或误导性指南可能部分修复但仍有残留。
- **固定VLM策略**：Agent的LLM本身从未更新，仅技能文件可变；对于需要学习新感知模式或动作原语的任务可能受限。
- **评估成本高**：MMG2Skill需要多轮VLM API调用（构造+执行+分析+精炼），对商业模型依赖大，实验重复性受API接口和预算限制。
- **早停信号在部分领域欠校准**：Strategy-MJ领域召回率仅49.5%，Hold'em私有信息场景精度仅9.9%，表明成功可推断性假设在某些任务上不成立，需外部验证。
- **指南表示形式依赖**：HTML+图像效果良好，但截图变体表现类似；对纯文本指南或视频格式未测试。游戏领域需预先过滤冗余图标资源，略微减少自动化程度。
- **算力未公开**：缺少训练/推理所需GPU规格和总运行时长，不利于可重复性评估。
- **应用伦理考虑**：增强Agent利用公共知识执行复杂操作的能力可能被滥用，论文虽强调仅在沙箱环境测试，但未提供具体防护建议。
