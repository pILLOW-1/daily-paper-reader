## 摘要
编码代理在解决软件工程任务时产生丰富的轨迹。为了使代理能够自我演化，这些轨迹可以被提炼为可重用的程序性技能，这些技能紧凑地编码经验以指导未来行为。然而，现有的技能构建和维护方法通常依赖于固定的提示和启发式更新规则，不清楚应如何选择、抽象和维护知识以最好地服务下游代理。我们提出CODESKILL，一个基于LLM的框架，将技能提取和技能库维护重新表述为可学习的管理策略。CODESKILL从编码代理轨迹中提取多粒度程序性技能，用新经验演化技能，并维护一个紧凑的技能库以解决未来任务。我们使用强化学习训练CODESKILL，采用混合奖励，结合基于详细评分标准的技能质量反馈和来自冻结下游代理的稀疏可验证执行反馈。在EnvBench、SWE-Bench Verified和Terminal-Bench 2上的实验表明，与无技能基线相比，CODESKILL将平均通过率提高了9.69，与最强的基于提示或记忆的基线相比提高了4.01，同时在迭代构建过程中保持技能库大小稳定。

## Abstract
Coding agents produce rich trajectories while solving software-engineering tasks. To enable agent self-evolution, these trajectories can be distilled into reusable procedural skills that compactly encode experience to guide future behavior. However, existing skill construction and maintenance methods often rely on fixed prompts and heuristic update rules, leaving it unclear how knowledge should be selected, abstracted, and maintained to best serve downstream agents. We propose CODESKILL, an LLM-based framework that reformulates skill extraction and skill-bank maintenance as a learnable management policy. CODESKILL extracts multi-granularity procedural skills from coding-agent trajectories, evolves skills with new experience, and maintains a compact skill bank for future task solving. We train CODESKILL with reinforcement learning, using a hybrid reward that combines dense rubric-based skill-quality feedback with sparse verifiable execution feedback from the frozen downstream agent. Experiments on EnvBench, SWE-Bench Verified, and Terminal-Bench 2 show that CODESKILL improves average pass rate by 9.69 over the no-skill baseline and by 4.01 over the strongest prompt-based or memory baseline, while maintaining the skill bank at a stable size during iterative construction.

- **研究动机**：让代理能够从自身经验中持续学习并自我进化，但当前的技能管理策略是非学习的，不能根据下游代理的实际反馈来优化技能的质量和实用性。
- **整体含义**：论文提出将技能管理本身视为一个可学习的策略，通过强化学习优化技能提取、演化和维护的决策过程，从而使编码代理在长时间跨度任务中更高效地积累和复用经验。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 使用一个独立的 LLM（初始化为 Qwen3.5-4B）作为技能管理器（policy Mθ），该管理器学习如何从编码代理的轨迹中提取多粒度技能、基于新经验演化现有技能、并通过添加、合并或丢弃操作维护技能库。
- 技能管理器通过强化学习（GRPO）进行训练，奖励信号由两部分组成：基于评分标准的技能质量奖励（密集）和来自冻结下游编码代理的稀疏可验证执行奖励（任务完成提升）。
- 训练采用三阶段课程：先训练提取，再加入演化，最后加入完整维护操作。

### 关键技术细节
- **技能表示**：每个技能是一个 Markdown 文件，包含标题、触发条件（when_to_apply）和可操作指令（rules）。分为两种粒度：
  - 任务级技能：捕获高层次的策略（如如何定位问题、验证修复）。
  - 事件驱动技能：捕获局部重复出现的执行事件（如命令失败、错误信息模式），可跨任务迁移。
- **操作空间**：包括 extract（生成新技能）、evolve（修订现有技能）、add（添加候选技能）、merge（合并重叠技能）、drop（丢弃冗余技能）、skip（跳过）。
- **技能管理循环**：
  1. **提取**：从单条或少量相关轨迹中提取新技能（任务级或事件级）。
  2. **演化**：将现有技能与新轨迹配对，输出修订后的技能。
  3. **维护**：候选技能进入维护阶段，根据当前技能库中的相似技能决定 add/merge/drop。
- **训练流程（配图Fig.2）**：
  - **监督预热**：使用教师模型（GPT-5.4-mini）从轨迹生成标签数据，训练模型学习操作格式。
  - **强化学习训练**：对每个提示 q 采样 G 个操作 {uj}，计算质量奖励（RQ）和执行奖励（RE = V(τ_u) - 基线得分）以及对齐奖励（RA）。最终奖励 R = λ RQ + RA * RE。使用 GRPO 损失函数更新策略。
  - **三阶段课程**：阶段1只训练提取；阶段2加入演化；阶段3加入完整维护。这种做法可以渐进式引入复杂操作，并使得前期生成的技能成为后期训练的数据源。
- **混合奖励设计**：
  - 质量奖励：LLM-as-judge 对技能的接地性、可重用性、特异性、格式、触发条件等多维度评分。
  - 执行奖励：对生成的技能，通过反向检索选取一个评估实例，运行带技能的冻结下游策略，对比无技能基线得分差。
  - 对齐奖励：判断下游代理的实际行为是否遵循了技能触发条件和指令。
- **算法1**（GRPO训练）详细描述了预缓存基线分数、对每个操作计算奖励、归一化优势、更新模型的过程。

## 3. 实验设计

### 使用的数据集/场景
- **EnvBench**：测试环境设置和依赖修复，包含 Python 和 Java 仓库。用于训练和评估，使用不相交的保留集（采样150个仓库）。
- **SWE-Bench Verified**：测试仓库级别的问题解决。随机采样150实例作为评估集，其余350用于RL训练。
- **Terminal-Bench 2**：基于终端的任务解决。完全未在训练中使用，作为分布外测试基准。

### 下游编码代理
- 主要实验使用 **Qwen3.5-35B-A3B** 作为冻结编码策略。
- 也测试了 **GPT-5.4-mini** 作为下游策略以验证跨策略泛化性。

### 对比方法
- **无技能基线（No-skill baseline）**：不使用任何记忆或技能。
- **子任务记忆（Subtask Memory）**：基于 Shen et al. 2026 的强记忆基线，分解轨迹为子任务并蒸馏记忆。
- **提示技能管理（Prompt Skill Mgmt.）**：使用与 CODESKILL 相同的操作空间和流程，但用固定提示替代可学习策略（使用 Qwen3.5-4B 或 GPT-5.4-mini 作为执行模型）。
- **SFT-CODESKILL**：仅经过监督微调，未经过强化学习的版本。
- **CODESKILL**：完整训练后的模型。

## 6. 论文的主要结论与发现

- **CODESKILL 显著提升下游编码代理性能**：在平均通过率上比无技能基线提升 9.69%（相对约33%），比最强提示/记忆基线提升 4.01%（相对约11%），且在所有基准（包括分布外 Terminal-Bench 2）上均表现最佳。
- **技能管理必须可学习**：固定提示和启发式规则的技能管理（即使使用强 LLM 如 GPT-5.4-mini）弱于经过下游反馈优化的可学习策略。
- **两种粒度技能互补**：事件驱动技能和任务级技能各自贡献，组合后效果更好。
- **演化操作进一步改进**：加入演化后，通过率从提取仅有的 38.63 提升到 40.75。
- **维护操作控制技能库大小**：完整生命周期管理使技能库从 1252 缩减到 676，同时性能略有下降但可接受，防止无限增长。
- **跨策略泛化**：即使在 GPT-5.4-mini 下游策略上，CODESKILL 仍然最优秀，表明学到的管理行为可迁移。
- **效率提升**：CODESKILL 减少成功实例的平均推理步数（从 44.12 降至 35.15），说明技能降低了搜索成本。

## 7. 优点

- **创新性**：将技能管理重新定义为可学习策略，并通过强化学习利用下游反馈进行优化，解决了传统固定规则方法的适应性不足问题。
- **混合奖励设计巧妙**：结合密集的评分标准（质量）和稀疏的执行信号（任务完成），使用对齐因子解决信用分配问题，使监督既细致又执行相关。
- **多粒度技能框架**：同时捕获高级任务策略和低级事件模式，覆盖不同抽象层次的可重用知识。
- **三阶段课程训练**：渐进式引入操作类型，利用中间输出作为后续阶段数据，有效缓解稀疏奖励下的训练困难。
- **实验设计全面**：涵盖多个基准、多种基线、消融实验、动态分析和跨策略验证，结果可信。
- **技能库稳定性**：通过自动合并/丢弃，技能库在足够演化步数后趋于稳定（图3），避免记忆无限膨胀。

## 8. 不足与局限

- **技能表示局限性**：当前技能仅限于自然语言指令，不能包含可执行脚本、API 定义或结构化资源，限制了表达能力。在代理可扩展工具集的场景中可能更有效。
- **操作空间限制**：每次只能对一个候选技能进行一个操作，无法直接表达复杂更新（如同时修订多个相关技能、拆分过宽技能、或执行批量操作）。未来需扩展。
- **依赖外部评判模型**：质量奖励和对齐奖励均依赖 GPT-5.4-mini 作为法官，引入额外计算成本及潜在偏见。虽然作者提到严格评分，但评判标准可能不完全一致。
- **训练计算成本高**：RL 约 210 小时在 4×H100 上，且需要预缓存基线得分（需多次无技能下游回滚），对资源要求较高。
- **实验覆盖范围**：虽然测试了分布外基准，但所有任务均为软件工程范畴（脚本/仓库任务），在不同类型代码任务（如 Web 开发、数据科学）上的泛化性未验证。下游策略仅测试了两种模型，可能需要更多变体。
- **消融实验中维护操作带来轻微性能下降**：虽然技能库缩减了，但通过率下降了约2%，说明当前维护机制可能过于激进或合并质量不完全，存在改进空间。
- **技能管理策略本身是一个 LLM**：当使用小模型（4B）时，初始 SFT 后效果有限，只有经过 RL 才显著提升，说明对基座模型的能力要求较高。
